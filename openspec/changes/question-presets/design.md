# Design

## Context

Зачем — proposal.md (Why); что видит игрок — дельты спеков `consequences/writing` и `consequences/reading`. Что важно для подхода:

- **Сервер не знает текстов вопросов.** `game-logic.js` знает только их число (`QUESTION_COUNT = 8`), а тексты — ключи `question1`–`question8` в `public/js/translations.js`, на обоих языках. Страница (`game-room.js`) берёт `question${step + 1}` для вопроса и для складок (`renderFolds`).
- **Раунд** — `game.round` (места, листы, шаг, кто держит чей лист, открытые листы, конец паузы). «Ещё раунд» и «Новый раунд» (`newRound`) обнуляют его, игра возвращается в лобби. Страницы получают раунд через `roundView`.
- **Хранилище комнаты** — формат ядра `gameToStorage`/`gameFromStorage`: объект игры как есть, новые поля сохраняются без правок ядра. Формат хранилища не меняется: комната, уснувшая на прежней версии, просыпается на новой с прежним раундом (ядро, Gotchas).
- **Выкладка не рвёт сокеты**: какое-то время рядом живут комната на новом коде и страница на старом, и наоборот.
- **Тесты идут и против прода** (`test:e2e:prod`): ни один браузерный тест не может выбрать набор раунда — он узнаёт его так же, как игрок.

## Goals / Non-Goals

**Goals:**
- Набор раунда выбирает сервер, один на всех. Страницы показывают его вопросы и название на своём языке.
- Раунд прежней версии доигрывается как «Классика». Хранилище и протокол только дополняются.
- Тесты проверяют выбор набора без повтора подряд и что каждый набор полон на обоих языках. Браузерные тесты не зависят от того, какой набор выпал.

**Non-Goals:**
- Выбор набора игроками и набор, который игроки сочиняют сами.
- Наборы разной длины: в каждом восемь вопросов, шаги и чтение не меняются.
- «Мешок» (все семь наборов по разу, потом заново): владелец выбрал только «не подряд».
- Память о прошлом наборе дольше жизни комнаты.

## Decisions

### Наборы — список имён на сервере, тексты — на страницах
`game-logic.js` получает список наборов `QUESTION_SETS` — их имена в коде: `classic`, `incident`, `heAndShe`, `fairyTale`, `detective`, `news`, `journey`. Раунд хранит имя своего набора (`round.questionSet`). Страница берёт тексты по ключам `<набор>Name` и `<набор>Question<n>`: `classicName`, `classicQuestion1` … `journeyQuestion8`. Ключи `question1`–`question8` становятся `classicQuestion1`–`classicQuestion8`.
- *Почему так*: сервер и сейчас не знает текстов, а страница показывает их на языке игрока. Название и вопросы набора меняются вместе с языком без запроса к серверу.
- *Отвергнуто*: сервер шлёт тексты. Тогда нужно слать оба языка, и тексты живут в двух местах.
- *Отвергнуто*: выбор на странице. Наборы на страницах разойдутся.
- `translations.test.js` держит списки вместе: у каждого набора из `QUESTION_SETS` есть название и восемь вопросов на обоих языках. Других ключей `…Question<n>` нет, старых `question<n>` тоже.

### Выбор при старте раунда, без повтора подряд
`startRound` выбирает набор случайно из `QUESTION_SETS` без прошлого набора комнаты и кладёт его в `round.questionSet`. Сама игра запоминает его в `game.lastQuestionSet`: раунд обнуляется в лобби, а игра — нет. Поле новое: `fields()` даёт `lastQuestionSet: null`.
- Прерванный раунд считается: набор записан уже при старте.
- Случайность — `Math.random`: набор не секрет, в отличие от кода комнаты. Функцию случайности тесты передают в `startRound` параметром (по умолчанию `Math.random`), так Jest проверяет выбор без повторов детерминированно.
- Память живёт столько же, сколько игра в хранилище комнаты: пустая комната через 2 часа стирается и забывает прошлый набор. Это принято (proposal).

### Раунд без набора — «Классика», и на сервере, и на странице
`roundView` отдаёт `questionSet: round.questionSet || 'classic'`. Страница так же читает раунд без поля как `classic`.
- Раунд, начатый до выкладки, проснётся без поля. Сервер отдаст «Классику» — это прежние вопросы, и игроки доиграют то, что начали.
- Комната, которая ещё работает на старом коде, шлёт раунд без поля. Новая страница в ней покажет «Классику», как и было.
- Игра прежней версии без `lastQuestionSet` выбирает из всех семи.
- Jest держит это тестом: раунд в форме прежней версии (без `questionSet`) читается как «Классика».

### Браузерные тесты узнают набор по названию над листом
Помощник в `tests/e2e/helpers.js` — `questionOf(page, step, lang)`. Он читает название набора на странице, находит набор, чьё `<набор>Name` на этом языке совпадает с названием, и отдаёт `text('<набор>Question<step>', lang)`. Тесты, которые ждали `text('question2')`, ждут `await questionOf(page, 2)`. Так тест действует как игрок, и тот же набор тестов идёт против прода.
- *Отвергнуто*: переменная Worker, которая задаёт набор в тестах. Против прода она недоступна, а тесты должны быть одни и те же.
- Новые браузерные тесты:
  - название над листом на обоих языках, после перезагрузки и на взятом листе отсутствующего;
  - название при чтении и над историями;
  - «Ещё раунд» даёт другое название.
- Сам выбор без повтора проверяет Jest. Браузерный тест проверяет один переход: следующий раунд не тот же. Это верно при любом выпавшем наборе.

### Где стоит название — решает владелец на странице вариантов
Это изменение вида, поэтому сначала страница вариантов. На ней реальные экраны письма, чтения и историй на русском, с названием набора в нескольких местах и видах. Владелец выбирает букву, потом идёт вёрстка. Разметка — элемент для названия в `game.html` (письмо) и в карточках чтения и историй, которые рисует `game-room.js`. Его вид — в `style.css`. Название рисует сценарий через `textContent`.

### Название в истории для друзей
`shareStory` в `game-room.js` ставит название набора первой строкой, через пустую строку от ответов: `★ <НАЗВАНИЕ> ★\n\n<ответы>\n\n<приглашение>`.
- Название берётся на языке страницы того, кто делится, как и приглашение. Набор страница знает из раунда (`round.questionSet`).
- *Почему капс со звёздочками* (выбор владельца): окно «Поделиться» передаёт простой текст, а жирный шрифт каждый мессенджер размечает по-своему. Капс между звёздочками везде выглядит одинаково и повторяет заголовки листов в игре. ★ — текстовый знак, не эмодзи: его рисует системный шрифт любого устройства.
- Тест `reading.spec.js` на «Поделиться историей» с `stubShare('record')` ждёт заголовок первой строкой. Тест копирования без Web Share ждёт его в скопированном тексте.

### Правило на главной и README
Правило `rule2` («Восемь вопросов: кто, с кем…») описывает один набор. Новый текст, на согласование владельцу:
- ru: «Восемь вопросов, и в каждом раунде свой набор: классика, сказка, детектив и ещё четыре»;
- en: «Eight questions, a new set every round: classic, fairy tale, detective story and four more».

README игры и корневой README говорят о наборах так же. Картинка превью ссылки (`og-image.jpg`) показывает лист «Классики» и остаётся: «Классика» — один из наборов.

## Risks / Trade-offs

- **[Старая страница в комнате на новом коде]** Страница, открытая до выкладки, не знает наборов. В раунде, начатом после выкладки, она покажет вопросы «Классики» под любым набором, пока её не перезагрузят. Ответы при этом не теряются. → Принято: окно короткое, комнаты во время выкладки редки, а перезагрузка всё исправляет. Баннер обновления здесь не помогает: `sw.js` не меняется, и менять его ради этого не стоит (ядро, PWA).
- **[Откат на прежнюю версию]** Прежний код не знает `round.questionSet`. Раунд, начатый на новом коде, покажет вопросы «Классики» вместо своего набора. → Принято: откат редок, следующий раунд снова цельный.
- **[Тексты на двух языках разойдутся]** Новый набор без английского или с девятью вопросами. → `translations.test.js` (решение выше).
- **[Тест против прода не узнал название]** Название не совпало ни с одним набором, например из-за опечатки в тексте. → Помощник падает с понятной ошибкой: «название над листом не совпало ни с одним набором».

## Migration Plan

1. Выкладка Consequences, минорная версия: формат хранилища тот же, ядро и whoami не меняются.
2. Раунды, начатые до выкладки, доигрываются как «Классика». Новые раунды идут с наборами.
3. Откат — прежняя версия из `master` (Risks: идущий раунд покажет «Классику»).
