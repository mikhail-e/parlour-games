# Design

## Context

Зачем — proposal.md (Why). Что важно для подхода:

- whoami в проде: `whoami.escapist.club`, Worker `whoami-game`, комнаты — Durable Objects класса `Room` (миграция `v1`). Workers Builds: root directory `/`, команда сборки пустая, выкладка `npx wrangler deploy -c games/whoami/wrangler.jsonc`, watch paths `games/whoami/*`, `package.json`, `package-lock.json` (`docs/release.md`). Пакеты ставятся `npm clean-install` в корне по корневому `package-lock.json` (спайк move-to-monorepo).
- Общий код уже отделён внутри игры и не знает её правил: `worker/room-base.js` и `public/js/room-socket.js` (`games/whoami/CLAUDE.md`, «The shared part»). Остальное, что выбрано в ядро, лежит вперемешку с кодом игры: в `utils.js`, `translations.js`, `worker/index.js`, `game-logic.js`, `style.css` (`@font-face`).
- Страницы — обычные `<script>`, без модулей и шага сборки; файлы делят имена верхнего уровня (`/* global */`, `/* exported */`, правило 7). `game-logic.js` — CommonJS: его тестирует Jest в Node, и Worker собирает его через esbuild.
- Из документации Cloudflare (проверено): у Worker одна папка статических файлов; Workers Builds выполняет свою Build command перед командой выкладки, но «does not honor» раздел `build` из `wrangler.jsonc`; сам wrangler выполняет `build.command` при `wrangler dev` и `wrangler deploy`. Как wrangler в Workers Builds собирает код из пакета workspace, не описано.
- Из кода wrangler 4.157 (проверено): при выкладке он обходит папку статических файлов и пропускает symlink по замыслу (`if (filestat.isSymbolicLink()) return`), но проверяет через `stat`, а не `lstat`, поэтому сейчас выкладывает файлы, на которые ссылки указывают. Папку-ссылку Node обходит или нет в зависимости от версии.
- Ключи в `localStorage`, которые whoami уже записала игрокам: `playerId`, `whoami-player-secret`, `whoami-language`, `whoami-debug`.

## Goals / Non-Goals

**Goals:**
- Всё, что выбрано в ядро, лежит в `packages/room-kit/` в одном экземпляре, и whoami берёт это оттуда.
- Вторая игра получает ядро без копирования кода, тестов и конфигов: подключает пакет, задаёт свой префикс ключей и свои словари.
- Шаг сборки не меняет ни одного файла, который отдаёт сайт, по содержимому: меняются только адреса.

**Non-Goals:**
- Новые возможности ядра «на вырост», для Consequences: ядро получает только то, что уже есть в whoami.
- Общий вид (`style.css`), общий `sw.js`, общие иконки.
- Собственные браузерные тесты ядра (страница-демо): поведение ядра проверяют браузерные тесты игр.
- Изменение значений: заголовков, таймингов сокета, сроков комнат, форматов, ключей хранилища.

## Decisions

### 1. Пакет workspace `packages/room-kit`, без своей версии

`packages/room-kit/package.json`: имя `@parlour-games/room-kit`, `private: true`, без поля `version`. Ядро выходит вместе с версиями игр: `/api/version` показывает версию игры, а у ядра нет ни своих тегов, ни выпусков. Корневой `workspaces` — `["games/*", "packages/*"]`; whoami указывает ядро в `dependencies` своего `package.json` (`"@parlour-games/room-kit": "*"`), чтобы связь была видна и `npm ls` её показывал. npm связывает такую зависимость с пакетом workspace и без версии (проверено на пробном workspace). Своих devDependencies у ядра нет, как у игр: инструменты — в корне.

Раскладка ядра повторяет игру, чтобы те же блоки ESLint и те же привычки работали в обоих местах:

```
packages/room-kit/
├── package.json        # имя, без версии, bin для копирования, scripts (lint, test), настройки Jest
├── CLAUDE.md, README.md
├── worker/             # ES modules, только для Worker: room-base.js, http.js (обвязка), security-headers.json
├── shared/             # CommonJS: identity.js (код комнаты, формат ID, хэш секрета) — Worker и Jest
├── public/             # что копируется в public/ игры, теми же путями
│   ├── _headers        # заголовки статических файлов и их причины
│   └── kit/            # js/ (room-socket, app, i18n, pwa, wake-lock), vendor/bootstrap/, fonts/ (+ fonts.css)
├── scripts/            # копирование public/ в игру (bin)
├── eslint.js, playwright.js, e2e.js   # общие части конфигов и сторож браузерных тестов
├── eslint.config.mjs   # ESLint самого ядра, на eslint.js
└── tests/              # Jest: проверки файлов ядра
```

Альтернатива — версия `0.0.0`, которая никогда не поднимается: номер, который ничего не значит. Отклонена. Альтернатива — не указывать зависимость: пакет всё равно слинкован в корневой `node_modules`, но связь игры с ядром нигде не записана. Отклонена.

### 2. Граница: ядро не знает игр

Ядро не содержит ни имён событий, ни текстов игры, ни правил, ни вёрстки конкретной игры, как и сейчас `room-base.js` и `room-socket.js`. Что переезжает, а что остаётся, — proposal.md (What Changes). Спорные места решены так:
- **Уведомления** (`showError`, `showInfo`, `showNotification`, `handleApiError`) остаются в `utils.js` whoami: они вставляются перед `.game-card`, это её вёрстка. Владелец не выбрал их в ядро.
- **Проверки ввода** (длины имён и персонажей, фото-аватар) остаются в whoami вместе с их двумя копиями и тестом.
- **Код комнаты и формат ID** переезжают; `game-logic.js` берёт их из ядра и экспортирует дальше под теми же именами, поэтому тесты и вызовы whoami не меняются.
- Правило «не уверен, куда класть, — клади в игру» остаётся.

### 3. Серверный код импортируется из пакета, собирает его wrangler

whoami импортирует серверные модули по пути в пакете (`@parlour-games/room-kit/worker/room-base.js`), `game-logic.js` — `require('@parlour-games/room-kit/shared/identity')`. npm кладёт в корневой `node_modules` ссылку на `packages/room-kit`, esbuild внутри wrangler идёт по ней и включает код ядра в бандл Worker, как любой пакет. `cloudflare:workers` в `room-base.js` wrangler оставляет внешним. `shared/` — CommonJS, как `game-logic.js`: его читают и Jest в Node, и esbuild; `worker/` — ES modules, его читает только esbuild. Поле `exports` в `package.json` ядра не задаётся: так любой файл пакета доступен по пути и для Node, и для esbuild, без второй карты путей.

Проверка — сначала локально (`npx wrangler deploy --dry-run --outdir` в папке игры: бандл собирается, в нём код ядра), затем в Workers Builds на временном Worker (решение 11).
Альтернатива — относительные пути (`../../../packages/room-kit/...`): работают без npm, но привязывают игру к раскладке репозитория и обходят зависимость из решения 1. Отклонена.

### 4. Браузерные файлы — копия при сборке (выбор владельца)

Скрипт ядра (`bin` пакета) накладывает `packages/room-kit/public/` на `public/` игры: появляются `public/_headers` и `public/kit/`. Это копии: в git их нет (`.gitignore`: `games/*/public/kit/`, `games/*/public/_headers`), правят их только в ядре. Копирование:
- **локально** запускает сам wrangler: в `games/whoami/wrangler.jsonc` раздел `build` — `command: "npm run build"`, `watch_dir` — папка `public/` ядра. Значит, `npm start` и оба сервера браузерных тестов (Playwright запускает `wrangler dev`) всегда стартуют со свежей копией, а `npm start` копирует заново, когда меняется файл ядра;
- **в Workers Builds** — Build command `npm run build -w games/whoami`: раздел `build` из `wrangler.jsonc` Workers Builds, по документации, не выполняет. Спайк показал: `wrangler deploy` в Workers Builds выполняет его ещё раз. Это безвредно: копирование идемпотентно, второй раз ничего не пишет (`docs/release.md`);
- пишет только изменившиеся файлы и каждый — через временный файл и переименование, удаляет из `public/kit/` то, чего в ядре больше нет. Два `wrangler dev` браузерных тестов копируют одновременно, и ни один не должен увидеть недописанный файл.

Страницы подключают файлы ядра по адресам `/kit/js/...`, `/kit/vendor/bootstrap/...`, `/kit/fonts/...`. Для игрока меняются только адреса: содержимое файлов то же.

Отклонено (вопрос 5 владельцу):
- **symlink в git** — держится на опечатке wrangler (Context): её исправление молча убрало бы файлы ядра с прода, а сборка и выкладка прошли бы без ошибок;
- **раздача Worker'ом** — каждый файл ядра стал бы запросом к Worker из дневного лимита бесплатного плана, хотя статические файлы бесплатны; плюс свои типы файлов и кеш;
- **копии в git с тестом на равенство** — каждый файл дважды, то, от чего ушли к монорепо.

### 5. Браузерный API ядра: те же глобальные имена, префикс ключей от игры

Скрипты ядра остаются обычными `<script>` и дают те же имена верхнего уровня, что сейчас (`RoomSocket`, `debugLog`, `AppStorage`, `PLAYER_ID`, `PLAYER_SECRET`, `i18n`, `getText`, `serverErrorText`, `keepScreenAwake`…) со своими `/* exported */`, поэтому код страниц whoami меняется только в списках `/* global */`. Состав файлов в `public/kit/js/`:
- `app.js` — `debugLog`, `AppStorage`, ID и секрет игрока, `PLAYER_ID_PATTERN`, `showAppVersion`;
- `i18n.js` — класс `Localization`, `i18n`, `getText`, `serverErrorText`, свои тексты ядра (баннер обновления и «Закрыть» — en и ru);
- `room-socket.js`, `pwa.js`, `wake-lock.js` — без изменений кода, кроме ссылок на соседние файлы в комментариях.

**Ключи хранилища.** Каждая игра на своём домене, поэтому ключи разных игр не пересекаются. Игра задаёт префикс в маленьком своём скрипте, который страницы подключают первым (`public/js/config.js`, `/* exported APP_STORAGE_PREFIX */`), и ядро пишет `<префикс>-debug`, `<префикс>-player-secret`, `<префикс>-language`, а ID — под ключом `playerId`, как сейчас. У whoami префикс `whoami`, и все четыре ключа совпадают с нынешними: тот же игрок, тот же секрет, тот же язык.
Альтернатива — `<meta>` в каждой странице: три копии одной строки. Отклонена.

**Словари.** `translations.js` игры оставляет только свои словари (`translations`, `serverErrors`) и подключается до `i18n.js`. Тексты, которые показывает код ядра, — в словаре ядра; словарь игры может их переопределить. Так вторая игра не обязана знать, какие ключи нужны ядру.

Порядок в `<head>`: `config.js` игры → `app.js` ядра → `translations.js` игры → `i18n.js` ядра → `utils.js` игры; в конце `<body>` — Bootstrap, `pwa.js`, `room-socket.js`, `wake-lock.js` ядра и скрипт страницы. `404.html` подключает то, что ему нужно для переводов.

### 6. Заголовки безопасности: один список в ядре (выбор владельца)

Обе копии — в ядре: `public/_headers` (для статических файлов, с причинами в комментариях) и `worker/security-headers.json` (для ответов Worker); тест ядра держит их равными. Значения переносятся байт в байт. Причины в `_headers` называют, какой игре нужен источник (у whoami `data:` и `blob:` для фото-аватаров; `screen-wake-lock`, Web Share и выбор фото не запрещены). Новый источник в CSP по-прежнему — сознательное решение с комментарием, теперь для всех игр сразу. Если игре понадобится своё сверх общего, это отдельное решение (свой список поверх общего), не в этом change.
`tests/e2e/site-headers.spec.js` whoami проверяет, что браузер получает заголовки и на статических файлах, и на ответах Worker: это ловит и сломанное копирование.

### 7. Обвязка Worker

`worker/http.js` ядра даёт игре рамку ответа: игра передаёт свою функцию маршрутов и версию из своего `package.json`, рамка отвечает `/api/version`, превращает HEAD в GET без тела, при исключении отвечает `{ success: false }` со статусом 500, ставит заголовки безопасности на всё, кроме принятого сокета, и отдаёт страницу 404 игры (`/404` из её статических файлов) на неизвестный адрес. Маршруты, `run_worker_first` и комнаты — игры. `worker/index.js` whoami становится короче, его ответы не меняются (`api.spec.js`, `not-found.spec.js`, `site-headers.spec.js`).

### 8. Bootstrap и шрифты (выбор владельца)

Bootstrap переезжает в `public/kit/vendor/bootstrap/` как есть, с лицензией. Шрифты — в `public/kit/fonts/` с лицензиями, а их `@font-face` (с `unicode-range` и `font-display`) — из `style.css` в `public/kit/fonts/fonts.css` ядра без изменений, кроме путей. Страницы подключают `fonts.css` перед `style.css`, `preload` Ultra в трёх страницах получает новый адрес. Цвета, занавес, листы и кнопки остаются в `style.css` whoami. Скрипты картинок (`scripts/icon.html`, `scripts/og-image.html`) берут шрифты и Bootstrap из папки ядра.

### 9. Общие конфиги: ESLint и Playwright (выбор владельца)

- `eslint.js` ядра даёт общие правила и блоки по средам с путями, одинаковыми у ядра и у игр: `worker/**` (Workers и их классы сокетов), `public/js/**` и `public/kit/js/**` (обычные скрипты, `no-console` кроме warn/error), `public/sw.js`, `tests/*.js` (Jest), `tests/e2e/**` и конфиги (Playwright), `shared/**` (CommonJS), игнор отчётов и `.wrangler/`. Игнор зависит от места: в игре `public/kit/` — копия, её не проверяют; в ядре там исходники, и игнорируется только `public/kit/vendor/` (чужой код). Поэтому игнор копии — параметр общей части, а не её постоянный блок. `eslint.config.mjs` игры — общие блоки, игнор копии и свой блок для `game-logic.js`.
- `playwright.js` ядра даёт команду `wrangler dev` для теста (свой порт, свой inspector, хранилище во временной папке, переменные), общие `use` (reducedMotion, service worker разрешён, traces off), проекты «телефон» (Pixel 7) и «компьютер», таймауты для `BASE_URL`. `playwright.config.js` игры задаёт свои порты и серверы.
- `e2e.js` ядра даёт сторож браузерных тестов: расширенный `test`, который роняет тест на нарушении CSP или ошибке в консоли, с теми же исключениями, что сейчас (запись трассы, ожидаемые 404). `tests/e2e/helpers.js` whoami строит свои помощники поверх него.
- Jest не делится: его настройки — одна строка.

### 10. Тесты переезжают с кодом, поведение проверяют игры

Решение владельца «у общего кода нет своих тестов поведения: его проверяют браузерные тесты игры» остаётся. Меняется только место проверок, которые читают файлы ядра:
- в ядро переезжают: равенство двух копий заголовков; равенство двух копий `PLAYER_ID_PATTERN` (обе теперь в ядре); `debugLog` на настоящем `app.js`; механизм переводов (подстановки, перевод ошибок, тексты ядра на обоих языках); запрет встроенных `style=`/`on…=` в скриптах ядра;
- ядро даёт играм проверки, которые нужны каждой игре: общие имена скриптов (берёт скрипты игры и ядра вместе) и запрет встроенного кода в страницах. Тесты whoami вызывают их, вторая игра вызовет так же, без копии;
- в whoami остаются: полнота её словарей, копии её ограничений ввода, все браузерные тесты (`connection.spec.js` по-прежнему проверяет сокет ядра через страницы whoami).

`npm test` ядра — ESLint и Jest; корневой `npm test` запускает его вместе с проверками игр.

### 11. Workers Builds и спайк на временном Worker

Настройки `whoami-game` после выпуска: Build command `npm run build -w games/whoami`; build watch paths — include `games/whoami/*`, `packages/*`, `package.json`, `package-lock.json`. Остальное как было. `packages/*` — а не только `packages/room-kit/*`: любой общий пакет может касаться всех игр, лишняя сборка ничего не стоит, а пропущенная оставила бы прод на старом ядре.

Спайк — как в move-to-monorepo: временный Worker `parlour-spike` с веткой прода `spike/room-kit`, в ней готовая ветка этого change, а в `games/whoami/wrangler.jsonc` имя `parlour-spike`, без `routes`, `workers_dev: true`. Проверяется: журнал сборки (Build command скопировал файлы; выполнил ли wrangler раздел `build` ещё раз), выкладка прошла, `/api/version` и `POST /api/create-game` отвечают, `/kit/js/room-socket.js` отдаётся с заголовками, весь браузерный набор whoami проходит против адреса спайка (`BASE_URL`), push с правкой только в `packages/` запускает сборку. Затем Worker и ветка удаляются. В репозиторий записываются только выбранные настройки и вывод: без поддомена workers.dev, ID аккаунта и фрагментов журнала.

**Итог спайка.** Всё подтвердилось, менять план не пришлось:
- Сборку запустил push с правкой только в `packages/room-kit/README.md`: watch path `packages/*` работает.
- Пакеты поставил `npm clean-install` в корне по корневому `package-lock.json`. Ссылка на ядро и его bin `room-kit-copy-public` на месте, wrangler взят из lockfile.
- Build command скопировал файлы ядра в `games/whoami/public/`.
- `wrangler deploy` выполнил раздел `build` из `wrangler.jsonc` ещё раз (custom build) и ничего не скопировал: всё уже было на месте. Значит, в Workers Builds копирование идёт дважды и безвредно. Build command всё равно остаётся, потому что этот путь документирован; раздел `build` нужен для `npm start` и тестов.
- Выкладка загрузила файлы `/kit/` и прошла. `/api/version` ответил версией whoami. `/game/<несуществующий код>` дал 302. `/kit/js/room-socket.js` и `/kit/fonts/fonts.css` отдались со статусом 200 и CSP. `POST /api/create-game` создал комнату.
- Браузерный набор whoami против адреса спайка (`BASE_URL`) прошёл. Исключение одно, и оно по замыслу: тест «the cards name the site they are served from» сверяет адреса в карточках ссылки с адресом сайта, а карточки держат адрес прода.
Альтернатива — сразу на прод: при ошибке копирования прод остался бы со страницами без скриптов и заголовков до отката. Отклонена.

### 12. Правила ядра — в его CLAUDE.md, игра их подключает

В `packages/room-kit/CLAUDE.md` (английский, как другие CLAUDE.md) переезжают правила из `games/whoami/CLAUDE.md`, которые описывают код ядра или платформу, общую для игр на ядре: общая часть, сокет и проверка соединения (ping, тишина, поиск замолчавших сокетов), вложения сокетов, заголовки безопасности и CSP, `debugLog`, общие имена скриптов, механизм переводов и `data-i18n*`, Bootstrap и шрифты, копирование в `public/kit/`, «сокет отбрасывает то, что не может отправить», выкладка не рвёт сокеты, локально Worker видит хост прода, миграции классов комнат, `public/` выкладывается как есть. В CLAUDE.md whoami остаётся то, что про игру, со ссылками на ядро, и строка `@../../packages/room-kit/CLAUDE.md`: Claude Code подключает такой файл всегда, когда читает CLAUDE.md игры, а сам по себе CLAUDE.md соседней папки он читает только при работе в ней. Ни одно правило не теряется и не пишется дважды.

### 13. Выпуск `whoami-v2.2.0`

Минорная версия: для игроков ничего не меняется, прежнее продолжает работать (открытые комнаты, сохранённое в браузере, установленное приложение). Выпуск — по `docs/release.md`; Build command и watch paths владелец меняет прямо перед push в `master`.

## Risks / Trade-offs

- [В Workers Builds копирование не прошло → страницы без скриптов, Bootstrap, шрифтов и заголовков] → спайк (решение 11); после выпуска `npm run test:e2e:prod` и `site-headers.spec.js`; откат версии Worker в панели.
- [Build command сменили раньше времени → сборка старого `master` падает (у него нет скрипта `build`)] → менять прямо перед push выпуска; упавшая сборка прод не трогает. Откат прода — версией в Deployments, без пересборки.
- [Локально устаревшая копия ядра] → wrangler копирует при каждом старте и при правке ядра (`watch_dir`); Jest читает файлы ядра из пакета, не из копии.
- [Два `wrangler dev` копируют одновременно] → копирование идемпотентно, файлы пишутся через переименование (решение 4).
- [Копии случайно попали в коммит] → `.gitignore`; проверка `git status` после `npm test` и `npm start`.
- [Новые адреса скриптов и шрифтов] → браузер один раз скачивает их заново; `sw.js` не меняется, баннера обновления нет; шрифты проверяет `styles.spec.js`.
- [После выкладки бодрствующая комната работает на старом коде рядом с новыми страницами] → протокол сокета и формат хранилища не меняются, класс комнат тот же.
- [Правка ядра ломает игру незаметно] → корневой `npm test` перед каждым слиянием проверяет все игры и ядро.
- [Claude Code не видит правил ядра при работе в игре] → импорт CLAUDE.md ядра в CLAUDE.md игры (решение 12).
- [Jest, ESLint или VS Code не находят пакет workspace] → проверки в группе 1 tasks.md до переноса кода.
- [Ядро растёт от догадок о второй игре] → в ядро идёт только то, что уже есть в whoami (Non-Goals); новое ядру добавит change Consequences.

## Migration Plan

1. Ветка `feature/room-kit` от `develop`; пакет ядра, `workspaces`, общий ESLint.
2. Копирование и статические файлы, затем серверный код, затем браузерный, затем Playwright; после каждой группы `npm test` из корня зелёный, документы этой группы написаны.
3. Полная проверка локально, спайк на временном Worker, итог — в этот design.md (решение 11) и `docs/release.md`.
4. Слияние в `develop` после скана непушенной истории на рабочие и личные данные; push `develop` (не собирается).
5. `release/whoami-2.2.0`; владелец меняет Build command и watch paths `whoami-game`; подтверждение владельца; push `master` и тега `whoami-v2.2.0`.
6. Проверка прода: сборка успешна, `/api/version` = `2.2.0`, `npm run test:e2e:prod -w games/whoami`, сайт открывается, внизу `v2.2.0`, комната, открытая до выкладки, жива.

Откат: сборка упала — прод на 2.1.0, исправить и пересобрать; выложено с ошибкой — предыдущая версия в Deployments (имя Worker, класс комнат и хранилище те же, откат безопасен), затем `hotfix/whoami-2.2.1`.
