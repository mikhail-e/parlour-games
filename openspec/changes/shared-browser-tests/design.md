# Design

## Context

Зачем — proposal.md (Why). Что важно для подхода:

- Браузерные тесты игры лежат в её `tests/e2e/`, Playwright запускает их по настройкам игры (`playwright.config.js` на общей части ядра, `packages/room-kit/playwright.js`): два проекта (`mobile`, `desktop`), свой `wrangler dev` и второй сервер с короткими таймерами комнаты. Игрок и страховка — `packages/room-kit/e2e.js`, помощники, которые действуют через страницы ядра, — `packages/room-kit/e2e-helpers.js`; `tests/e2e/helpers.js` игры передаёт их дальше со своими (`text`, `serverErrorText` из `pageTexts` её `translations.js`).
- Образец общего теста уже есть: `packages/room-kit/e2e-check-tag.js` экспортирует `checkTagTest()`, а `tests/e2e/check-tag.spec.js` каждой игры — одна строка, которая его вызывает. Тест регистрируется на `test` из `e2e.js` ядра, тот же объект, что берёт игра.
- Решение владельца: поведение ядра проверяется через страницы игр, а не на своей странице ядра (`packages/room-kit/CLAUDE.md`, Decisions). Значит, общий тест должен идти в каждой игре, на её страницах и её сервере.
- Тексты ядра (`KIT_TEXTS`) игра может заменить своим текстом под тем же ключом (`packages/room-kit/CLAUDE.md`, Translations): ожидание общего теста — текст страницы игры, то есть её `text`.
- Тесты, которые есть в обеих играх (ревью тестов, находки 10 и 11), и где они лежат сейчас:

| Тест | whoami | Consequences |
|---|---|---|
| ссылка на несуществующую комнату | `site.spec.js` | `landing.spec.js` |
| имя и аватар запоминаются после создания и после входа | `landing.spec.js` | `landing.spec.js` |
| два игрока с одним именем | `room.spec.js` | `landing.spec.js` |
| фото вместо эмодзи видят все | `custom-avatar.spec.js` | `landing.spec.js` |
| выход из лобби, Leave во всех вкладках, последний удаляет комнату | `leave-and-return.spec.js` | `room.spec.js` |
| Copy Link | `share.spec.js` | `room.spec.js` |
| комната без страниц уходит; пока все страницы закрыты, никто не уходит | `room-timers.spec.js` | `room-timers.spec.js` |
| ничего с чужих сайтов, заголовки на адресах, версия, иконки, «Update now» | `site.spec.js`, `site-headers.spec.js` | `site.spec.js` |
| страница 404 и адреса без неё | `not-found.spec.js` | `not-found.spec.js` |
| карточки превью, `robots.txt`, `llms.txt` | `link-preview.spec.js` | `link-preview.spec.js` |

- `GameRoom.hasGame()` (`/game/CODE`) только читает: вопрос о комнате не двигает её таймер и ничего не пишет (`packages/room-kit/worker/game-room.js`).

## Goals / Non-Goals

**Goals:**
- Каждый общий тест написан один раз и идёт в каждой игре на её страницах, как раньше.
- Названия тестов не меняются: отчёт и поиск по названию находят их, как прежде.
- Где копии разошлись, общий тест проверяет всё, что проверяла хотя бы одна из них.

**Non-Goals:**
- Тесты, которые есть только в одной игре, даже если они проверяют ядро (стражи `e2e.js` в `site.spec.js` whoami, вход по коду в нижнем регистре, полная комната): их копий нет.
- Своя страница ядра для тестов.
- Изменение кода игр или ядра, кроме файлов тестов.

## Decisions

### 1. Общие тесты — функции модуля ядра, которые регистрируют тесты

`packages/room-kit/e2e-kit-tests.js` экспортирует группы: `landingPageTests`, `roomPageTests`, `roomTimerTests`, `siteTests`, `notFoundTests`, `linkPreviewTests`. Функция вызывает `test(...)` из `e2e.js` ядра, а игра вызывает функцию в своём spec-файле той же темы, со своими параметрами: `text` из своего `helpers.js` во всех группах, `brand` (название игры, как его читает экранный диктор: `aria-label` вывески, `og:site_name`) у 404 и карточек.

Почему не общий spec-файл в ядре, который подключает `testMatch` каждой игры: параметры игры (её тексты, её название) пришлось бы передавать через переменные окружения, а запуск одного файла игры и настройки проектов усложнились бы. Почему не одни общие помощники: тогда остаются копии самих тестов, а находка именно о них. `e2e-check-tag.js` уже идёт этим путём, второй образец не нужен.

### 2. Игра вызывает группу в файле той же темы

| Группа | whoami | Consequences |
|---|---|---|
| `landingPageTests` | `landing.spec.js` | `landing.spec.js` |
| `roomPageTests` | `leave-and-return.spec.js` | `room.spec.js` |
| `roomTimerTests` | `room-timers.spec.js` | `room-timers.spec.js` |
| `siteTests` | `site.spec.js` (сюда же переходит цикл адресов из `site-headers.spec.js`) | `site.spec.js` |
| `notFoundTests` | `not-found.spec.js` | `not-found.spec.js` |
| `linkPreviewTests` | `link-preview.spec.js` | `link-preview.spec.js` |

Файлы игр остаются с теми же именами: CLAUDE.md игр ссылаются на них (`not-found.spec.js` проверяет `.assetsignore`, `link-preview.spec.js` держит две карточки равными), и ссылки остаются верными. `roomTimerTests` вызывается после `test.skip` и `test.use` файла игры (сервер с короткими таймерами, без прода, один браузер): группа не задаёт их сама, потому что у Consequences в том же файле есть свои тесты таймеров с теми же условиями.

### 3. Где копии разошлись, общий тест берёт обе проверки

- выход из лобби: имя на главной заполнено (whoami) и у уведомления о выходе есть значок (Consequences);
- 404: вывеска игры на странице (Consequences; у whoami на 404 та же вывеска, `aria-label="Who am I?"`);
- иконки: и `link rel="icon"`/`apple-touch-icon`, и иконки манифеста как PNG (Consequences);
- регистрация service worker (Consequences);
- «Update now»: значок на баннере (Consequences);
- адреса с заголовками: `/sw.js` (Consequences). Файл игры в списке — `/js/config.js`: он есть у каждой игры на ядре по договору ядра (его префикс ключей), а `game-room.js` — имя, которое ядро не задаёт.

whoami получает проверки, которых у неё не было. Если какая-то упадёт, это находка о самой игре, её разбирают отдельно, а не ослабляют тест.

### 4. Запросы без страницы — один браузер

Тест, который только шлёт запрос и разбирает ответ, пропускается на телефоне: `test.skip(({ isMobile }) => isMobile, 'HTTP only: one browser is enough')`, как `api.spec.js`. Это заголовки на адресах (комнату для адреса «a room» создаёт страница, но проверяется ответ сервера), адреса 404 без страницы и вся группа карточек: карточка — разметка `<head>`, которую бот читает без браузера, а размер картинки меряет та же страница на компьютере. Правило записывается в `docs/testing.md` ядра. Страницы на телефоне проверяются по-прежнему: устройство меняет то, как страница рисуется, а не что отвечает сервер.

### 5. «Комната уходит» ждёт условие, а не 9 секунд

Тест спрашивает `/game/CODE` без перехода (`maxRedirects: 0`) через `expect.poll`, пока ответ не станет переадресацией (302), с таймаутом больше времени пустой комнаты сервера тестов; потом страница открывает ссылку и попадает на главную с сообщением. Вопрос к комнате ничего в ней не меняет (Context), так что опрос не продлевает ей жизнь. Тест «пока все страницы закрыты, никто не уходит» оставляет паузу: его предмет — сам промежуток без страниц, и правило 4 `docs/testing.md` («ничего не произошло» проверяется в известный момент) требует выждать его до конца.

### 6. Общие помощники — в `e2e-helpers.js`

`listedNames(page)` (имена карточек игроков по порядку, без «(You)»), `avatarTiles(page)` (плитки `#avatarSelector .avatar-option`), `axeViolations(page, only)` (WCAG 2.1 AA через axe, с выключенными CSS-переходами в таблице стилей игры `/css/style.css`, которую страница на ядре грузит последней), `sleep(ms)` (только тестам таймеров: там время — предмет теста). Игра передаёт их дальше из своего `helpers.js`, как остальные помощники ядра.

### 7. Повторы, которые просто удаляются

- `language.spec.js` whoami: «an unknown text key shows the key itself» — вызов `i18n.getText` через `page.evaluate`, то есть юнит-тест ядра в браузере (`packages/room-kit/tests/i18n.test.js`); «an unknown language falls back to English» — выбор языка проверяет тот же Jest-тест ядра, а что страница берёт язык браузера, уже показывает «a Russian browser gets Russian».
- `reading.spec.js` Consequences: «two players: each reads the sheet the other finished». Кому какой лист, решает сервер (Jest `test.each([2, 3, 12])` в `game-logic.test.js`), страница рисует присланный ей лист одинаково при любом числе игроков, это проверяет тест на трёх игроках.

## Risks / Trade-offs

- [Общий тест падает в одной игре из-за её разметки] → Так и задумано: поведение ядра проверяется на страницах каждой игры, и отчёт Playwright называет проект и файл игры, из которого тест вызван.
- [Место теста в отчёте — файл ядра, а не игры] → Playwright показывает место вызова `test()`. Найти тест можно по названию (`-g`), а прогнать файлом игры (`npx playwright test tests/e2e/landing.spec.js`) — как раньше. `docs/testing.md` ядра говорит об этом.
- [whoami получает новые проверки, и они падают] → Решение 3: разбирать как находку о игре.
- [Меньше прогонов на телефоне] → Ответ сервера от устройства не зависит. Страницы, которые тест открывает, проверяются на телефоне по-прежнему.
- [Опрос адреса комнаты в тесте таймеров шлёт запросы] → Только локальному серверу с короткими таймерами: против прода тест пропускается, как и раньше.

## Migration Plan

Только тесты: ничего не выкладывается, выпуск игр не нужен. Откат — revert слияния ветки в `develop`.
