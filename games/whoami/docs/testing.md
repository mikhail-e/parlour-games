# Тесты

Все проверки игры — `npm test` в её папке: ESLint, затем Jest, затем браузерные тесты Playwright. Перед слиянием ветки — `npm test` из корня репозитория: он гоняет проверки каждой игры. CI нет: этот прогон — единственная проверка до `develop` и прода.

## Команды

Из папки игры, `games/whoami/`. Скрипты npm то же самое делают из корня с `-w games/whoami` (`npm run test:e2e -w games/whoami`); `npx jest` и `npx playwright` — только из папки игры: их настройки лежат в ней.

```bash
npm test                                   # всё
npm run lint                               # только ESLint
npx jest                                   # только Jest
npx jest tests/game-logic.test.js          # один файл Jest
npm run test:e2e                           # только браузерные тесты
npx playwright test tests/e2e/room.spec.js --project=desktop   # один файл в одном проекте
npm run test:e2e:headed                    # с видимым браузером
npm run test:e2e:ui                        # интерактивный режим Playwright
npm run test:e2e:prod                      # браузерные тесты против прода (после выкладки)
```

На новом компьютере один раз: `npx playwright install chromium`.

## Два вида тестов

| Что | Где | Чем |
|---|---|---|
| Правила игры: `game-logic.js`, хранение и таймеры комнаты, проверка ввода, сверка копий, которые проект держит намеренно, правила того, как написан код | `tests/*.test.js` | Jest, в Node |
| То, что видит и делает игрок: страницы, кнопки, окна, несколько игроков в одной комнате; что видит бот мессенджера по ссылке на игру; стили, как их прочитал браузер; ответы HTTP API | `tests/e2e/*.spec.js` | Playwright, в Chromium |

Куда писать тест:
- **правило игры** — Jest, функция из `game-logic.js` вызывается напрямую;
- **маршрут HTTP** — Playwright, `tests/e2e/api.spec.js`;
- **всё, что игрок видит или делает** — браузерный тест;
- **новый экран или окно** — ещё и проверка axe в `accessibility.spec.js`.

Поведение проверяется через страницы и ответы сервера, а не поиском по коду. Тест, который ищет в файле `navigator.share`, остаётся зелёным, когда кнопка сломана. Код игры тест к себе тоже не копирует: копия подтверждает сама себя.

Правила о том, как написан код, тест проверяет по тексту файлов: правило и есть про текст. Так устроены:
- `code-structure.test.js`: ни `style="..."`, ни `on...="..."` в страницах и в HTML, который собирают скрипты (CLAUDE.md, правило 8; проверка — `inlineCodeProblems` ядра);
- сверка копий, которые проект держит намеренно: лимиты ввода в `game-logic.js` и `utils.js`, тексты ошибок сервера и их перевод (`serverErrors` в `translations.js`), общие имена скриптов страниц — игры и ядра вместе (`shared-names.test.js`, проверка ядра `sharedNameProblems`), список кеша service worker, манифест. Копии, которые держит ядро (заголовки безопасности, формат ID игрока), сверяют тесты ядра.

## Проекты Playwright

| Проект | Устройство |
|---|---|
| `mobile` | Pixel 7 — первым: в игру играют с телефонов |
| `desktop` | Chrome на компьютере |

Общие настройки — у ядра (`packages/room-kit/playwright.js`: проекты, `use`, таймауты для прода, команда `wrangler dev`); `playwright.config.js` игры задаёт свои порты и серверы. Только Chromium (решение владельца, CLAUDE.md). Playwright сам запускает два `wrangler dev` — движок Cloudflare с Worker, комнатами и файлами, как на проде, — и каждый раз заново, так что тесты всегда видят текущий код (а wrangler перед стартом копирует в `public/` файлы ядра):
- на порту 3100 — обычный, для всех тестов;
- на порту 3101 — с короткими таймерами комнаты (`--var ROOM_EMPTY_MS:8000 --var GHOST_MS:3000`): на нём идёт только `room-timers.spec.js` (`test.use({ baseURL: process.env.E2E_FAST_TIMERS_URL })`), остальные тесты его не трогают.

Запущенный `npm start` (8787) не мешает. Хранилище комнат оба пишут во временные папки (`--persist-to`), а не в `.wrangler/`.

В тестах язык браузера — английский, анимации Bootstrap выключены (`reducedMotion`), service worker включён, как у игроков. Проверка axe отключает на странице CSS-переходы: иначе цвет кнопки, который меняется под пальцем, замеряется на полпути. Правило вписывается в собственную таблицу стилей страницы (`insertRule`): добавленный тег `<style>` CSP заблокировала бы.

Все тесты идут под той же Content Security Policy, что и прод: её ставят `public/_headers` (копия из ядра) на файлы и Worker на свои ответы. Страница ничего не грузит с других сайтов (`site-headers.spec.js` это проверяет), так что интернет нужен только прогону против прода.

## Игроки и страховка

Игроки и страховка — у ядра (`packages/room-kit/e2e.js`): `tests/e2e/helpers.js` берёт оттуда `test` и `expect` и строит на них свои помощники.

`newPlayer(имя, { locale })` открывает отдельный профиль браузера на устройстве текущего проекта: у каждого игрока свой localStorage, а значит свой ID. После теста профили закрываются.

Страховка: тест падает, если на странице любого игрока случилась ошибка JavaScript, `console.error`, нарушение Content Security Policy (фикстура превращает его в `console.error` с названием правила) или неожиданное окно `alert`/`confirm`. Одно нарушение страховка пропускает: его создаёт сам Playwright, когда записывает трассу упавшего теста и копирует картинку страницы с адреса `blob:`. Тест, который ждёт такое событие, говорит об этом явно: `player.expectDialog(текст)` (окно принимается), `player.allowConsoleError(шаблон)`.

## Помощники (`tests/e2e/helpers.js`)

| Помощник | Что делает |
|---|---|
| `text(ключ, язык, подстановки)` | строка из `translations.js` (или из текстов ядра) — тексты игры в тестах не пишутся руками |
| `serverErrorText(текст, язык)` | ошибка сервера (он отвечает по-английски) так, как её показывает страница на этом языке |
| `seedStorage(игрок, значения)` | кладёт значения в localStorage игрока (ключи игры хранят JSON) |
| `waitForLanding(page)` | ждёт, пока главная страница подготовится (12 аватаров) |
| `createRoom(игрок)` | создаёт комнату с главной, возвращает код |
| `joinRoom(игрок, код)` | ссылка на комнату → `/?join=КОД` → имя → «Join» |
| `askToJoin(игрок, код)` | то же в начатую игру: страница комнаты ждёт, пока игрока впустят (`#waitingSheet`) |
| `playerCard(page, имя)` | карточка игрока; своя подписана «Имя (You)» |
| `waitForPlayers(page, число, { timeout })` | ждёт столько карточек |
| `roomWith(newPlayer, имена)` | комната этих игроков, все на её странице и видят всех |
| `assignCharacter(игрок, кому, персонаж)` | «+ Assign character», ввод, Enter |
| `startGame(игрок)` | «Start Game» и ожидание начатой партии |
| `revealOwnCharacter(игрок)` | свой конверт → окно → подтверждение |
| `startedGame(newPlayer, имена)` | целая начатая партия: комната, вход, персонажи по кругу, старт |
| `leaveGame(игрок)` | «Leave» → окно → подтверждение → главная |
| `stubShare(page, 'record' / 'abort' / 'unsupported')` | подменяет системное окно «Поделиться» (настоящее остановило бы браузер); вызывать до загрузки страницы |
| `countSentEvents(page, событие)` | считает события, которые страница отправила в сокет комнаты; вызывать до входа в комнату |
| `holdRoomJoin(page)`, `releaseRoomJoin(page)` | медленная связь: страница рисует комнату после HTTP-входа, а `join-room` её сокета уходит только после `releaseRoomJoin`; вызывать до загрузки страницы |
| `pngFile()` | настоящая PNG-картинка, собранная в коде |

## Сокет комнаты в тестах

Страница говорит с комнатой через `RoomSocket` ядра (`packages/room-kit/public/kit/js/room-socket.js`); внутри `page.evaluate()` он доступен как `socket`.
- **Обрыв связи** — `socket.ws.close()`: страница сама подключается снова (через секунду-другую) и входит в комнату заново. Так проверяются ход во время обрыва (`game.spec.js`) и новичок, у которого оборвалась связь (`late-join.spec.js`). С `context.setOffline(true)` до закрытия новое подключение не удастся, пока сеть не вернут.
- **Второй сокет из консоли** — `new RoomSocket(`/ws/${код}`)`: так игрок-злоумышленник пробует действовать за других (`impersonation.spec.js`, `late-join.spec.js`).
- **Придержать вход** — `holdRoomJoin` подменяет `WebSocket.prototype.send` до загрузки страницы и придерживает кадр с `"event":"join-room"`; остальные кадры уходят сразу.
- **Таймеры комнаты** (2 часа без страниц, час для «призраков») проверяет `room-timers.spec.js` на втором сервере, где это секунды. Против прода он пропускается.
- **Адрес в карточках превью** (`link-preview.spec.js`, «the cards name the site they are served from») проверяется только против развёрнутого сайта (`BASE_URL`): в разметке записан адрес прода, локальный сервер с ним не совпадает. Только в проекте `desktop`: карточки — разметка, телефон ничего не добавляет.

## HTTP API

`api.spec.js` проверяет ответы `/api/*` и ссылки на комнаты через `request` Playwright — без страницы, только в проекте `desktop`: телефон тут ничего не добавляет. Он идёт и против прода.

`wake-lock.spec.js` держит свою подмену `navigator.wakeLock` — экран, который не гаснет, из теста не увидеть. Подмена ведёт себя как браузер: выдаёт блокировку, отказывает скрытой странице, снимает блокировку, когда страница уходит с экрана (`setPageHidden`), и по просьбе отказывает в первом запросе. Последний тест спрашивает настоящий Chromium с разрешением `screen-wake-lock`: подмена не знает, просит ли страница то самое и пускает ли это `Permissions-Policy` сервера. Без разрешения Chromium отказывает, как телефон в режиме экономии, — и молчание отказа проверяет страховка всех тестов начатой партии.

## Правила набора

1. **Ожидания берутся из данных игры** (`translations.js`, ответы сервера), а не переписываются руками: копия в тесте расходится с игрой при первой правке и начинает подтверждать сама себя.
2. **Новый тест хотя бы раз ломают.** Тест на исправление падает на старом коде (из папки игры: `git stash push public worker game-logic.js`, прогон, `git stash pop`); тест на уже работающее поведение падает, если на минуту испортить код игры. Тест, который не падает на сломанной игре, ничего не проверяет.
3. **Никаких пауз «подождать 2 секунды»** (`waitForTimeout`): тест ждёт условие, `expect(...)` сам повторяет проверку.
4. **«Ничего не произошло» проверяется в известный момент.** `expect(...).not...` ждёт, пока условие станет верным, а надпись «✅ Copied!» и уведомления исчезают сами — такой тест проходит и на сломанной игре. Состояние читается один раз после точки синхронизации: сразу после вызова (`share.spec.js`) или после события, которое пришло позже (`game.spec.js`, «Cancel in the reveal window»).
5. **Каждый тест создаёт свою комнату**: тесты идут параллельно и не мешают друг другу, в том числе на проде.
6. **Действовать как человек**: сначала страница готова, потом клик (`waitForLanding`); элемент, который пропускает касание сквозь себя, нажимается в точке, где он нарисован (`page.mouse.click`).
7. **Пропуск — только с причиной**: `test.skip(условие, 'почему')`.
8. **Селекторы**: роли и подписи (`getByRole`), `id`, `data-*`. Если зацепиться не за что — добавить подпись (`aria-label` с переводом) или `data-*`: подпись поможет и экранному диктору.

## Отладка

- Трассы по умолчанию не пишутся: запись делает снимок страницы после каждого действия каждого теста, и в полном параллельном прогоне эта нагрузка изредка подвешивала страницу — тест падал при исправной игре. Разобрать падение: прогнать с трассой (`npx playwright test <файл> --trace on`, плавающий тест — вместе с `--repeat-each`) и открыть её: `npx playwright show-trace test-results/<тест>/trace.zip`. Отчёт прогона — `npx playwright show-report`.
- `npm run test:e2e:headed` или `npm run test:e2e:ui`, чтобы видеть страницу.
- Журнал игры в консоли: `await player.page.evaluate(() => localStorage.setItem('whoami-debug', 'on'))` и перезагрузка.
- Плавающий тест — прогнать много раз: `npx playwright test <файл> --repeat-each=10`.

## Против прода

`npm run test:e2e:prod` гоняет те же браузерные тесты против https://whoami.escapist.club — после каждой выкладки (`docs/release.md` в корне репозитория). Тесты создают на проде свои комнаты. Комнату удаляет последний вышедший; остальное убирает сама комната: игроков «не в сети» дольше часа, пока кто-то играет, и комнату через 2 часа после того, как закрылась последняя страница. Таймауты больше, а браузеров одновременно два (`--workers=2` в команде), а не половина ядер, как дома: до прода идёт настоящая сеть, и чем больше игроков разом, тем вероятнее, что какой-то ответ не успеет до таймаута. Прогон расходует дневной лимит запросов Cloudflare, общий для всех приложений владельца (корневой CLAUDE.md, Decisions).
