# CLAUDE.md - "Who am I?" Game

One game of the parlour-games monorepo: the repository's layout, commands, git flow and decisions are in the root `CLAUDE.md`. Paths here are from this folder, `games/whoami/`.

The game is built on the shared kit, `packages/room-kit/`; the kit's rules hold here too:
@../../packages/room-kit/CLAUDE.md

## Project Overview
Web application to play the "Who am I?" guessing game remotely with friends and family. Players join a room by a 6-character code, assign secret characters to each other, then guess who they are. Adaptive UI works on desktop and mobile browsers; installable as a PWA.

- **Production:** https://whoami.escapist.club/ (Cloudflare Workers, free plan)
- **Repository:** https://github.com/mikhail-e/parlour-games, folder `games/whoami/` — public, a showcase (root CLAUDE.md, Decisions)
- **Stack:** Cloudflare Workers + Durable Objects backend (one Durable Object per room, `wrangler`); vanilla JavaScript (ES6+) + Bootstrap 5 frontend (the kit's local copy); Jest and Playwright for tests. No frontend framework and no bundler: the only build step copies the kit's files into `public/` (`npm run build`, run by wrangler itself).

## Commands
In this folder; from the repository root the npm scripts take `-w games/whoami` (`npm start -w games/whoami`). Installing the packages and the once-per-machine steps: root CLAUDE.md.
```bash
npm start                          # wrangler dev: copies the kit's files (npm run build), then the Worker, its rooms and the files on http://localhost:8787
npm test                           # The game's checks: ESLint, Jest, then Playwright (before a merge: npm test at the root, every game's)
npm run lint                       # ESLint only (any warning fails); npm run lint:fix fixes what it can
npx jest tests/game-logic.test.js  # Run a single Jest file (in this folder only: Jest's settings are in its package.json)
npm run test:e2e                   # Browser tests only (Playwright); :headed and :ui variants
npm run test:e2e:prod              # Browser tests against production (after a release)
npx wrangler tail whoami-game      # The live log of production; production is deployed by Workers Builds from master, never by hand
```

### How it works
- **Rooms are Durable Objects:** one per 6-character room code (e.g. `ABC123`), found by the code (`env.ROOMS.getByName(code)`); a room keeps its one game in its storage. The static files of `public/` are served without the Worker (they cost nothing of the day's request limit); `run_worker_first` in wrangler.jsonc sends `/api/*`, `/game/*` and `/ws/*` to `worker/index.js`, and `/game`, `/index`, `/404` too: the static files would answer those with a page, the game answers its 404 page
- **HTTP API:** every address is the kit's (`packages/room-kit/CLAUDE.md`, The Worker's frame): `POST /api/create-game`, `POST /api/join-game`, `GET /game/:roomCode` (game.html, or home with `?error=room-not-found`), the room's socket `/ws/CODE`, `GET /api/version` (the version from package.json, shown in the footer of both pages by the kit's `showAppVersion()`), HEAD, a failure (`{ success: false }`, status 500) and any address nothing else answers (`public/404.html`, status 404)
- **Security headers:** the kit's one list for every game (`packages/room-kit/CLAUDE.md`, Security headers) on every answer: its copy `public/_headers` puts them on the static files (pages, files, the 404 page, their redirects), and the Worker on its own answers (API, room pages, its redirects). An accepted socket's answer goes back without them. Of the list, whoami is the game that needs `data:` and `blob:` images (photo avatars, below) and leaves the screen wake lock and Web Share allowed; `tests/e2e/site-headers.spec.js` checks what a browser gets
- **Socket events:** the room page's socket is the kit's `RoomSocket` on `/ws/CODE`, its room the kit's room with players (`packages/room-kit/CLAUDE.md`, The room with players): `join-room`, `ask-to-join` and `leave-game` are the kit's, and so is the rule that **who acts is the player the socket is registered for**, never an ID from the message. whoami's moves (`MOVES` in worker/room.js): `assign-character`, `start-game`, `reveal-character`, `restart-game`, and for a newcomer to a started game `admit-player`, `decline-player` (below); they carry only what the move needs (`assign-character`: the target `playerId` and the `character`). The broadcasts reach every player socket, the sender's included — intentional, keep it so. The page sends its moves through the kit's `sendMove()`, which holds them while the socket is (re)joining or not connected (`packages/room-kit/CLAUDE.md`, The room page)
- **Leaving:** the kit's (`leave-game`: only themselves, in all their tabs; a late page answered `player-left` too; the last player deletes the room — `packages/room-kit/CLAUDE.md`, The room with players); here the leaver's character and reveal status go with them. The `player-left` broadcast carries the full state; the kit's room page takes the leaver home with the code ready (`/?join=CODE`), and the kit's landing page remembers the name and avatar (`whoami-player-name` / `whoami-player-avatar`: the kit's keys under whoami's prefix; `packages/room-kit/CLAUDE.md`, The landing page)
- **Returning to a started game:** a leaver of the round comes back to their place with the same browser, without asking anybody (the kit's `recentlyLeft` snapshot, `packages/room-kit/CLAUDE.md`, The players of a room); whoami's part of the snapshot is the character, reveal status and sticker color (the hooks in game-logic.js). A stranger has to ask (below). Restart clears the snapshots. The `player-joined`/`player-reconnected` broadcasts carry `characters`/`revealedPlayers` so other clients see the restored character reappear
- **Joining a started game:** a newcomer waits on their room page, the way of the kit (`waitingForApproval`, `ask-to-join`, the socket's role `waiting`, a request living as long as their waiting pages, at most 12 players and waiting newcomers together — `packages/room-kit/CLAUDE.md`, The room with players and The players of a room); the room page shows the kit's waiting screen (`#waitingSheet`, `packages/room-kit/CLAUDE.md`, The room page) — here the wax seal with an arc running round it; `body.waiting-for-admission` hides the room. whoami lets them in by a player's answer: any player answers in `#joinRequestModal` (`admit-player` / `decline-player`); the first answer decides, a later one gets "This request has already been answered", which the page drops silently. Every end of a request reaches the players as `join-request-closed` and the newcomer as `join-request-ended`: `declined` sends them home (`/?join=CODE&error=join-declined`, they may ask again), `retry` makes the page join again and follow the answer - let in (`admitPlayer`: last in the list, the secret recorded), the lobby after a restart, or a room that is gone. A newcomer is let in only while there is a seat (a leaver returning to the round may take it first: `admitPlayer` answers "Game is full" and the request stays). The window has a static backdrop and no ×: only its buttons close it (otherwise a player could lose the request with no way back); requests queue, wait for another open window to close (`hidden.bs.modal`), and a page that opens gets the ones still waiting with `game-state` (`joinRequests`). The let-in newcomer has no character: their own card shows `.character-sticker.mystery.open-envelope` ("empty for now", nothing to press), the others get "+ Assign character" on it. So the room keeps inviting during a round: the room code ticket stays in the header, and the lobby's invitation (`#inviteCard`, with the link field, at the top) gives way to a shorter one below the game controls (`#gameInviteCard`: a line saying a newcomer will ask, Copy Link and Share) — the round's screen starts with the players
- **Player list order:** the kit's first-join order (`packages/room-kit/CLAUDE.md`, The players of a room), identical on every client — no client-side sorting
- **Persistence:** the room saves its game after every change and loads it when it wakes, in the kit's stored form (`gameToStorage` / `gameFromStorage`: everything as it is, the characters and reveals included; `packages/room-kit/CLAUDE.md`, The players of a room): nothing lives only in memory (the kit's room base, The room). `tests/stored-round.test.js` loads a round an earlier version saved. A room no page of a player has open is deleted after the kit's empty-room time (`ROOM_EMPTY_MS`), the last player leaving deletes it at once; the room's timer (alarm) does it, at the kit's `roomAlarmTime()`
- **Player identity:** one UUID per browser stored in `localStorage.playerId` (the kit's `PLAYER_ID`, `packages/room-kit/CLAUDE.md`, The player in the browser). **The ID is public** (every page in a room sees the players list), so a second UUID per browser proves who a browser is: the secret, `localStorage['whoami-player-secret']` (`PLAYER_SECRET`). Every join sends it (`/api/join-game` refuses one without it), and `join-room` registers a socket only with it; how the server records and checks it — by ID only, never by name, so two players may have one name — is the kit's (`packages/room-kit/CLAUDE.md`, The players of a room). The server keeps only a hash of each secret (one browser uses one secret in every room); the hashes stay in the room's storage: never in a broadcast, an answer or the log (the kit's `forLog`)
- **Timeout protection:** the page and the room notice a connection that died without a word (the kit's connection check: the page's pings and reconnects, the room's sweep of silent sockets, which this room's timer calls every minute while sockets are open) — a phone asleep with its socket open. Disconnected players are marked `isConnected: false` rather than removed, so they can reconnect; ghosts — players offline for over the kit's hour, only while a page of a player is open, with fresh clocks after a gap (`packages/room-kit/CLAUDE.md`, The players of a room) — are removed by the room's timer and broadcast as a regular `player-left`. Here the price of the hour is a ghost in the lobby keeping Start disabled for up to that hour, unless someone gives it a character; in a started game the `recentlyLeft` snapshot still lets the same ID return
- **Keep screen awake:** while a round is on — from Start until every envelope is open, or until Restart — the room page holds a screen wake lock (the kit's `keepScreenAwake()`, called from `updateGameDisplay()`, so a reload or a return to a started round takes it too): players look at the others' tags for minutes without a touch. No timer: a phone left on the table during the round stays lit, after the last envelope it sleeps as usual. How the lock is taken and taken again is the kit's (`packages/room-kit/CLAUDE.md`, Screen wake lock); `tests/e2e/wake-lock.spec.js` checks the real Chromium lock too
- **Connection tracking:** the kit's — the sockets' roles in their attachments, two tabs as one player, offline with the last socket, the bookkeeping put right as a room loads (`packages/room-kit/CLAUDE.md`, The room with players). On page refresh the new socket often connects *before* the old one closes. `isConnected` is the server's bookkeeping only — the page does not show it
- **The kit and the game:** what knows nothing of the game is the kit's (`packages/room-kit/`, its CLAUDE.md) — the room with players, the Worker's frame and the rooms' addresses, room codes, the player's identity and the players list, the page scripts (the landing page's form, the room page — entering, the waiting screen, leaving, the invitation —, notifications and input limits, the socket, debug output and storage, translations and the shared parts' texts, the wake lock, the PWA and its service worker), the security headers, the playbill look, Bootstrap and fonts, the commands that take the icons and the link preview picture. The game's part is `worker/room.js` (its moves), `game-logic.js` (its rules and its hooks for the players list), the pages' markup, style.css (its sign and field), `game-room.js` (its field and events), and its brand: the sign, the icon's and the preview's sources. The kit's behaviour is tested through this game's browser tests. When unsure where code goes, it goes into the game's part

## Rules (important!)
1. **Bump the icon cache version in `CACHE_NAME`** (public/sw.js, e.g. `whoami-game-v1.6.0` → `v1.6.1`) **when you change the icons** (drawn in `scripts/icon.html`, taken by `npm run icons`). Only icons are cached, so HTML/CSS/JS changes reach players without it. This is not the app version — that one is in package.json (root `docs/release.md`)
2. **No code duplication across files** — code every game shares goes to the kit (`packages/room-kit/`), the game's shared frontend code to `public/js/utils.js`
3. **Update tests whenever logic changes**: a game rule → Jest with `game-logic.js`; what the player sees or does → a browser test in `tests/e2e/` (`docs/testing.md`). Run `npm test` before committing
4. **Localize all UI text** — every user-facing string of the game needs both `en` and `ru` entries in `public/js/translations.js` (the kit's rule and its `data-i18n*` attributes: `packages/room-kit/CLAUDE.md`, Translations). `tests/translations-real.test.js` fails if a key exists in only one language or repeats one of the kit's texts. An error the server sent is shown through `serverErrorText()`
5. **Never build DOM from user data with `innerHTML`** — player names and characters go through `textContent` (see `updatePlayersList()` in game-room.js; the kit's alerts do the same)
6. **Debug output goes through `debugLog()`** — the kit's rule (`packages/room-kit/CLAUDE.md`, Rules); here it prints after `localStorage.setItem('whoami-debug', 'on')` and a reload. The Worker's and the rooms' `console.log` is in Workers Logs (`observability` in wrangler.jsonc; live: `npx wrangler tail whoami-game`)
7. **The pages share names through plain `<script>` files** — the kit's rule (`packages/room-kit/CLAUDE.md`, Rules). The game's scripts take the kit's names (`debugLog`, `getText`, `showNotification`, `currentGame`, `sendMove`, `startRoomPage`, `keepScreenAwake`…) and give the kit `APP_STORAGE_PREFIX` (config.js), `translations` and `serverErrors` (translations.js); `tests/shared-names.test.js` checks the game's scripts and the kit's together
8. **Only the game's own code runs on its pages** — the kit's rule (`packages/room-kit/CLAUDE.md`, Rules): no `style="..."` or `on...="..."` attributes; here looks go through classes in the style sheets (the kit's playbill.css, the game's style.css). `tests/code-structure.test.js` checks the game's pages and scripts, the browser tests' guard any other blocked code

## Gotchas
- **Sticker colors are picked by the server** (`stickerColors` in game-logic.js); the browser only renders `player.stickerColor` as the `color-<name>` class, so every color needs a `.character-sticker.color-<name>` rule in style.css (`tests/improved-sticker-colors.test.js` checks). The rule sets `--deep`: the pin and the letters of the character's tag.
- `game-logic.js` must stay free of Cloudflare imports (CommonJS, Node's `crypto` through `nodejs_compat`) so Jest tests it in Node; its functions take a `Map` of games, and a room passes a Map of its one game
- Validate on the server, not just in the UI: `sanitizePlayerName` / `sanitizeAvatar` / `sanitizeCharacter` enforce the input limits, `assignCharacter` refuses to change characters once `state !== 'waiting'` (a late `blur` event can arrive after Start Game) - except a first, non-empty character for a player who has none (a newcomer let into the round), and `startGame` refuses while a player has no character (someone can join at the moment Start is pressed)
- **A character's length limit (128) exists twice** — the server's in `game-logic.js` and `public/js/utils.js` for the browser (a browser script cannot `require()` a Node module); `tests/input-limits.test.js` fails if they drift apart. Counted by character, not UTF-16 code unit, like a name, so an emoji counts as one and is never cut in half. The name's and the photo avatar's limits are the kit's, with their own pair (`packages/room-kit/CLAUDE.md`, The players of a room)
- **A photo avatar** (the kit's landing page, `packages/room-kit/CLAUDE.md`, The landing page) is stored in the same `player.avatar` field the emoji uses, so the room's storage and every broadcast carry it for free; game-room.js shows it only through the kit's `renderAvatar()` (`img.src` behind `isCustomAvatar()`), never `innerHTML`
- **Server error texts exist twice** — the server answers in English, and `serverErrors` in translations.js holds the Russian copies of whoami's own errors (game-logic.js, worker/), keyed by the English text; the kit's errors have their copies in the kit (`packages/room-kit/CLAUDE.md`, Translations). `tests/translations-real.test.js` fails if a text the server sends has no copy, a copy outlives its text or repeats the kit's. Rewording a server error means rewording its key too; game-room.js also compares `'This request has already been answered'` itself (its `ignoreError`, given to the kit's room page)
- `game-room.js` rebuilds the whole players list (`updatePlayersList()`) on updates instead of patching individual stickers — per-sticker DOM patching caused sync bugs, don't reintroduce it. Rebuilds are **skipped while a character input is open**, so anything that ends editing (game start, socket error) must call `cancelActiveEdits()` first or the UI freezes
- Dynamic text rendered from JS (game status, player cards) does not react to `data-i18n`. The kit's `setLanguage()` fires a `languagechanged` event; game-room.js listens and re-renders. Prefer static markup for controls (like `#shuffleAvatars`) so `data-i18n*` and keyboard focus just work
- **Hover effects only for a mouse** — the kit's rule (`packages/room-kit/CLAUDE.md`, The playbill look) holds in style.css too: a tapped tag would stay straightened (`tests/e2e/styles.spec.js` checks both style sheets)
- Mobile virtual keyboard: call `input.focus()` synchronously inside the click handler (no `setTimeout`) — otherwise iOS/Android won't open the keyboard
- Character assignment: players cannot assign a character to themselves; submitting empty/whitespace text removes the assignment (the card returns to the "+ Assign character" button). Escape restores the original character
- Sticker colors are assigned once when a player joins and never change; unique for up to 7 players, then cycled. Exception: your own hidden character renders as `.character-sticker.mystery` — a sealed envelope with a wax seal `span.seal` "?" (the wax is the app icon's, drips and all: `img/seal.svg`, a deliberate copy of `scripts/icon.html`'s seal that `tests/wax-seal.test.js` keeps equal; the "?" is the span's text), deliberately NO player color — until revealed; a newcomer let into a started round sees it unsealed (`open-envelope`) until a player gives them a character. A revealed player's card gets the class `revealed` (gold paper, a gold ring round the tag)
- **Characters are tags pinned to the cards**: every other card's tag leans the other way (`:nth-child(even)`; the list is in join order everywhere, so each tag leans the same way for everybody). A tag is a flex box, so a long word needs `overflow-wrap: anywhere` — `break-word` lets it run out of the tag (`room.spec.js` checks a 128-letter word). On a phone (style.css's `max-width: 768px` block) the names and tags are written larger: players read them at arm's length, the phone on the table. "+ Assign character" on someone else's card is a real `<button>` (`btn btn-outline-primary add-character-btn`, text from `assignCharacter`) built by game-room.js
- **Share and Copy Link are the kit's invitation** (`packages/room-kit/CLAUDE.md`, The room page): the lobby's (`#copyLink`, `#inviteButton`, with the link field) and a started round's (`#gameCopyLink`, `#gameInviteButton`, without it). Tests use `stubShare()` (the kit's helper, `packages/room-kit/e2e-helpers.js`) — a real click opens the OS share sheet, which blocks automation. Headless Chromium lets a page write and read the clipboard only with `grantPermissions(['clipboard-read', 'clipboard-write'])`: `share.spec.js` reads the copy back that way, and with `clipboard-read` alone it tests the fallback
- **Browser tests run with `reducedMotion: 'reduce'`** (Bootstrap modals open without their fade), and axe scans with CSS transitions switched off: `.mobile-modal-btn` animates its own color change, which reduced motion does not stop, and a color measured half-way fails contrast. The rule goes into the page's own stylesheet with `insertRule`: an added `<style>` tag is inline code the CSP blocks. A check that "nothing happened" reads the page once at a known moment — a flash like "✅ Copied!" disappears by itself (`packages/room-kit/docs/testing.md`, rule 4)
- **The Content Security Policy allows `data:` and `blob:` images** (the kit's list) for the kit's photo avatars: they are `data:image` URLs, and an uploaded photo is opened at a `blob:` address before it is shrunk. Everything else — scripts, styles, connections (the room's WebSocket included), fonts — only from the game's own site. Buy Me a Coffee is therefore the kit's plain link (`.bmc-button` in the landing page footer, `packages/room-kit/CLAUDE.md`, The playbill look): here English in both languages like the sign, its name the words it shows (`lang="en"`). The browser tests' guard fails on any violation; the one it ignores is the test tool's own: a trace Playwright records (a run with `--trace on`; traces are off by default, `packages/room-kit/docs/testing.md`) fetches a `blob:` image of the page
- **The sign** ("WHO AM I?", drawn after escapist-web's) is an inline `<svg class="brand-sign">` in three deliberate copies — index.html and game.html (the `h1`), 404.html (a `<p>`: its `h1` is "Page not found"); `tests/brand-sign.test.js` keeps them equal. Unlike escapist-web's drawing, the name is Ultra and has no shadow copy: Abril's hairlines under the dark copy were hard to read. It is a logo: English in both languages, `aria-label="Who am I?"`, and its `h1` carries **no** `data-i18n` (a translation would replace the drawing with text) — the page's language shows in the subtitle and the tab title. Its fonts come from style.css by class: a `<style>` inside the SVG is inline code the CSP blocks. The stars are polygons: no font of the game has ★, the system font would draw it differently on every phone. `npm run og-image` takes the sign from index.html, and escapist-web can take `svg.brand-sign` from production
- **Fonts are the kit's files** (`/kit/fonts/`, its `fonts.css` linked before the kit's playbill.css and style.css in the three pages; `packages/room-kit/CLAUDE.md`, Fonts): Fira Sans Condensed sets all the text (narrow like a playbill, yet easy to read; it replaced Oswald, whose tight letters were hard to read in sentences). The sign: Ultra (no Cyrillic) draws its name, Oswald (Latin 600 only) its two small lines; Abril Fatface draws only the seal's "?" (and the app icon's, `scripts/icon.html` takes the font from the kit); Ultra has a `preload` in the three pages: a logo flashing in a fallback serif looks worse than a short pause. `styles.spec.js` checks the faces load, Cyrillic included, and the envelope test in `game.spec.js` checks Abril
- **Colors are the kit's tokens** (`packages/room-kit/CLAUDE.md`, The playbill look: `--paper`, `--ink`, `--accent`, `--red`…, Bootstrap repainted through its variables); style.css adds the game's own paper on its `:root` (`--tag-paper`, `--envelope`, `--revealed-paper`). whoami's accent and curtain are the kit's defaults, red: it sets none of its own. **Red only for accents and for what cannot be undone** (Reveal, Leave, Restart). The app's color `#7e1a13` (the top of the curtain) is written in the three pages' `theme-color` and in the manifest (`tests/manifest.test.js` keeps them equal)
- **Link preview tags live in two copies** — the `<head>` of index.html and game.html (the room link is the one players share). A messenger's bot runs no scripts, so the card's text is fixed markup, not `data-i18n`, and its addresses are absolute: they hold the production domain (`docs/publishing.md` lists every place). game.html has no `og:url` (one file serves every room) and has `noindex`; rooms are never closed in robots.txt, which would also stop X's card. `tests/e2e/link-preview.spec.js` reads the pages as a bot does and keeps the two cards equal. The picture is taken from `scripts/og-image.html` by `npm run og-image` (the kit's command, `packages/room-kit/CLAUDE.md`, Pictures); messengers keep a picture by its address, so a new look gets a new file name (`og-image-2.jpg`, written in both cards: the command saves the picture where the landing page's `og:image` points)
- **The room socket drops what it cannot send** (the kit's Gotchas): a move goes through the kit's `sendMove()`, which waits for the room. Tests drop a connection with `socket.ws.close()` and hold a page's `join-room` with `holdRoomJoin()` (the kit's helper; it wraps `WebSocket.prototype.send`; `packages/room-kit/docs/testing.md`)
- **A deploy keeps the sockets open** (the kit's Gotchas): for a while a room may run the old code next to new pages. A room that Cloudflare does restart drops its sockets: the pages reconnect, and this game's room puts its bookkeeping right as it loads (Connection tracking)
- **`public/` is uploaded as it is** (the kit's Gotchas): this game's `public/.assetsignore` names `.DS_Store`; `_headers` and `.assetsignore` themselves are not served (`not-found.spec.js` checks)
- **PWA link capturing is a platform matter, not a bug.** iOS cannot open links in an installed web app at all (Apple limitation — links always open the browser/webview; no web-side fix exists). Android (installed via Chrome) captures in-scope links because `scope: "/"` covers `/game/*`; messenger in-app browsers bypass this. `launch_handler: navigate-existing` in manifest.json makes a captured link reuse the open app window (Android/desktop). `tests/manifest.test.js` guards these fields
- **The service worker caches icons and nothing else** — the kit's logic (`packages/room-kit/CLAUDE.md`, PWA); `public/sw.js` holds only the cache name and the icons, and `tests/service-worker.test.js` fails if HTML/CSS/JS is added to the list. **Any change to sw.js, even a comment, is a new worker** (and so is a change to the kit's `service-worker.js`): every open page shows the "Update available" banner, so edit it only for a real reason

Git flow, releases and hotfixes are the repository's: root CLAUDE.md and `docs/release.md`; this game's name in its branches and tags is `whoami`. A room lives in its own storage and keeps its sockets across a deploy (the kit's Gotchas): a game in progress goes on

## Decisions (why it is so)
The owner's decisions, with the reason. The repository's own — one repository for the games, a public showcase, no CI, Cloudflare's free plan, OpenSpec, how docs are written — are in the root CLAUDE.md.
- **The version is written only in package.json**: the server reads it (`/api/version`), the pages ask the server — no copy to keep in sync
- **Online only, no offline mode**: a room lives on the server (see the service worker gotcha above)
- **Locally `wrangler dev`**, the Cloudflare runtime on the Mac: the Worker, its rooms and the files together, as in production
- **Browser tests in Chromium only** — a phone (Pixel 7) and a desktop, like the owner's other apps; WebKit (Safari) is not covered
- **Behaviour is tested through the pages, never by searching the code**: a test that looks for `navigator.share` in a file stays green while the button is broken. Tests act like players — through pages, buttons and the server's answers, never through server memory — so the same suite runs against production, and no test keeps its own copy of the game's code. A rule about how the code is written may be checked by reading the files (`tests/code-structure.test.js`), like the checks of the deliberate copies listed in the gotchas
- **The look follows the sign**: a parlour-game playbill — cream paper with a rule inside its edge, dark brown ink, the sign's red — on a theatre curtain; characters are tags pinned to the player cards, your own a sealed envelope; the app icon is the envelope's wax seal
- **The link preview card is in English**, like the owner's other apps: a bot cannot pick the reader's language
