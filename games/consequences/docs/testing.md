# Тесты

Общие правила тестов игр на ядре — `packages/room-kit/docs/testing.md`: команды, два вида тестов, проекты Playwright, игроки и страховка, помощники ядра, сокет комнаты в тестах, правила набора, отладка, прогон против прода. Здесь — своё у Consequences.

## Команды

Из папки игры, `games/consequences/` (из корня — `-w games/consequences` для скриптов npm).

```bash
npm test                                   # всё: ESLint, Jest, Playwright
npx jest tests/game-logic.test.js          # один файл Jest
npx playwright test tests/e2e/writing.spec.js --project=desktop   # один файл в одном проекте
npm run test:e2e:prod                      # браузерные тесты против https://story.escapist.club
```

## Что проверяют тесты по тексту файлов

- `code-structure.test.js`: ни `style="..."`, ни `on...="..."` в страницах и скриптах игры (`inlineCodeProblems` ядра);
- `shared-names.test.js`: общие имена скриптов страниц — игры и ядра вместе (`sharedNameProblems` ядра);
- `translations.test.js`: оба языка словаря, одинаковые подстановки, словарь не повторяет тексты ядра, у каждой ошибки сервера есть русская копия (`translationProblems` ядра), у каждого набора все его тексты: название, вопросы, подсказки, заголовки;
- сверка копий, которые игра держит намеренно: предел ответа и наименьшее число игроков в `game-logic.js` и в `utils.js` (`input-limits.test.js`), три копии вывески (`brand-sign.test.js`), перо на иконке и на печати конверта (`seal.test.js`), цвет приложения в страницах, манифесте и `--curtain-top` (`manifest.test.js`), список иконок service worker (`service-worker.test.js`: только иконки, и все они есть).

## Серверы тестов

Playwright запускает два `wrangler dev` (`playwright.config.js`):
- на порту 3200 — обычный, для всех тестов; пауза после последнего ответа шага на нём почти нулевая (`STEP_PAUSE_MS: 50`): тесты играют много шагов;
- на порту 3201 — с короткими таймерами комнаты (`ROOM_EMPTY_MS: 8000`, `GHOST_MS: 3000`, `STEP_PAUSE_MS: 3000`, `LATE_ALARM_MS: 30000` — будильник смены шага опаздывает, как иногда бывает в Cloudflare): на нём идёт только `room-timers.spec.js` (`test.use({ baseURL: process.env.E2E_FAST_TIMERS_URL })`).

Порты whoami — 3100 и 3101, так что прогоны двух игр не встречаются; запущенный `npm start` (8788) тоже не мешает.

## Помощники (`tests/e2e/helpers.js`)

Файл передаёт дальше помощники ядра (`packages/room-kit/docs/testing.md`, Помощники ядра: тексты страниц, вход, создание комнаты, выход, новичок, медленная связь…) и добавляет свои — для раунда. Ответ по умолчанию называет автора и шаг: «Anna 3» — ответ Ани на третий вопрос, так что по истории видно, какое место что написало.

| Помощник | Что делает |
|---|---|
| `text(ключ, язык, подстановки)`, `serverErrorText(текст, язык)` | тексты `translations.js` игры поверх текстов ядра (`pageTexts` ядра) |
| `setOf(страница, язык)` | набор вопросов раунда — по заголовку на экране, как его видит игрок: листа при письме (название набора), листа при чтении («Сказки готовы»), всех историй («Все сказки») |
| `setText(страница, ключ, язык)`, `questionOf(страница, номер, язык)`, `hintOf(страница, номер, язык)` | текст набора раунда (`setText(page, 'AllStories')`), его вопрос с этим номером (1–8) и подсказка под ним |
| `questionsOfSet(набор, язык)`, `storyLines(набор, ответы, язык)` | восемь вопросов набора по порядку, те, что стоят над ответами истории; строки истории для друзей: каждый ответ после своего вопроса |
| `startRound(игроки)`, `startedRound(newPlayer, имена)` | «Начать» у первого и ожидание первого вопроса у всех; целая комната с начатым раундом |
| `answer(игрок, текст)` | ответ в поле и «Сохранить и передать» |
| `answerStep(игроки, шаг, ответ?)` | каждый отвечает на вопрос шага, ожидание следующего шага у всех |
| `writeByMoves(игроки, { from, to, answerOf })`, `writeToReading(игроки, ответ?)` | ответы на вопросы шагов ходами страницы (`sendRoomMove`), а не через поле: для теста, предмет которого после письма (поле и его кнопка проверены в `writing.spec.js`); все шаги до чтения |
| `waitForStep(игроки, шаг)`, `roundStep(страница)` | шаг раунда, каким его знает страница (`currentGame.round.step`: 0–7 вопросы, 8 чтение, `null` в лобби) — на любом языке |
| `returnToRound(игрок, код)` | возврат в идущий раунд по ссылке: главная, имя, «Войти» — и стол раунда, а не лобби (`joinRoom` ядра ждёт карточку лобби) |
| `seatRow(страница, имя)` | строка стола с этим именем (своя — «Имя (Вы)») |
| `holdMouseOn(страница, кнопка)` | мышь нажата на кнопке и держится; отдаёт отпускание: между ними другой игрок делает ход |
| `listeningPlayer(newPlayer, имя)`, `listeningRoom(newPlayer, имена)`, `messagesOf(игрок, событие)`, `latestMessage(игрок, событие)` | игрок, страница которого запоминает всё, что получают её сокеты комнаты, и комната таких игроков; все сообщения события и последнее из них |
| `sendRoomMove(игрок, событие, данные)` | ход так, как его шлёт страница (`sendMove` ядра), без кнопки |
| `countingSent(newPlayer, событие)` | игроки, страницы которых с самого начала считают отправленные события (`игрок.sent()`, на `countSentEvents` ядра): что отмена не отправила ход, тест читает после ответа комнаты на следующий ход, а не сразу после нажатия |
| `soundPlayer(newPlayer, имя)`, `soundsPlayed(страница)`, `lookAt(игрок, куда)`, `tapPage(игрок)` | звук (`sound.js`): игрок, страница которого запоминает каждый тон, о котором просит браузер, и сколько звуков она сыграла (ноты одного звука делаются в один момент, а тоны, сделанные порознь, это разные звуки); куда смотрит игрок: `'here'` на игру, `'tab'` на другую вкладку (вкладка игры скрыта), `'window'` в другое окно (окно игры видно, но не в фокусе); касание страницы там, где ничего нет: без касания или клавиши браузер не даёт странице звучать |

## Особые тесты

- **Тайна ответов**: `secret.spec.js` читает каждое сообщение, которое получают сокеты страниц, и ходит ходами страницы (`sendRoomMove`), а не кнопками: ему важно, что уходит по сети, а не что видно. Так же он проверяет историю комнаты: раунд, прерванный при письме, и идущий раунд не отдаются по `history-round`, а странице ожидающего новичка комната не отвечает ничем из истории.
- **История комнаты**: `history.spec.js` тем же способом проверяет, что комната хранит раунд, дошедший до чтения, и отдаёт его только спросившей странице. Раунды для окна «Все истории» и листа «Сыгранные раунды» он пишет ходами, как и все тесты, кроме тестов письма, а окном и лобби пользуется как игрок: листает раунды, делится историей прошлого раунда, держит окно открытым, пока другой игрок заканчивает раунд и начинает новый. Кнопки листания лежат под последней историей: что их не видно до конца окна, проверяется только на телефоне, на компьютере две истории стоят рядом и кнопки видны сразу.
- **Талон «Антракт»**: `coffee.spec.js` подменяет сайт Buy Me a Coffee заглушкой в браузере каждого игрока (`context.route`): нажатие на табличку по-настоящему открывает новую вкладку, а на чужой сайт ничего не уходит, и против прода тоже. Что талон переживает перерисовку листа чтения, тест видит по сообщениям сокета (`listeningPlayer`): другой игрок перезагружает страницу, и тест ждёт два `round-state` у нажавшего, прежде чем смотреть на талон. «Новая комната» в нём настоящая: тот же браузер создаёт другую комнату и доходит до чтения с новым игроком (игрок, уже бывший в комнате, входит по ссылке новой комнаты без главной страницы, и `joinRoom` ядра его не ждёт).
- **Шапка комнаты**: `room-header.spec.js` меряет ленту ламбрекена во время раунда: от верха окна, от края до края, код под названием по центру, и что страница не прокручивается вбок. Полосы прокрутки в Chromium тестов скрыты, поэтому случай, когда полоса занимает место и `100vw` шире страницы (Windows, Mac с постоянными полосами), тест не видит: его закрывает `overflow-x` в `style.css`, проверенный вручную браузером с видимыми полосами.
- **Набор вопросов**: тест не выбирает набор раунда — те же тесты идут против прода, — а читает его с экрана (`setOf`) и ждёт тексты этого набора. Выбор без повтора подряд проверяет только Jest (`game-logic.test.js`, с подставленной случайностью): в браузере новый набор совпадает с прошлым по случайности, и проверка «набор другой» прошла бы и на сломанном выборе. Полноту текстов каждого набора на двух языках, подсказки к вопросам тоже, держит `translations.test.js`.
- **Звук**: `sound.spec.js` не слышит звука. Скрипт инициализации (`soundPlayer`) записывает на странице каждый тон, о котором она просит браузер, и тест считает звуки (`soundsPlayed`): звук считается, только если контекст звука на странице работал, то есть игрок до этого коснулся страницы, как в жизни. Playwright держит каждую страницу видимой и в фокусе, поэтому «игрок не смотрит» тест сообщает странице сам (`lookAt`), подменяя `document.visibilityState` и `document.hasFocus`. Что звук не просит разрешений и ничего не грузит, тест видит, обернув на странице `Notification.requestPermission`, `navigator.permissions.query` и `getUserMedia` и собрав её запросы. Что звук правда слышен во вкладке в фоне, проверяется руками.
- **Нажатие во время чужого хода**: мышь нажата на конверте, на «Прочитать за» (`reading.spec.js`) или на сыгранном раунде (`history.spec.js`), другой игрок делает ход, страница его показывает, мышь отпущена, и кнопка срабатывает; фокус клавиатуры на конверте переживает чужой ход. Только в проекте компьютера: касание на телефоне Chromium ищет в момент отпускания и не теряет.
- **Гонки**: «Ответить за» у двоих сразу (`writing.spec.js`) — лист достаётся одному, другой видит, кто пишет, и никакого окна с ошибкой: проигранная гонка — не сбой (`LOST_RACES` в `game-room.js`).
- **Экран не гаснет**: `writing.spec.js` спрашивает настоящий Chromium с разрешением `screen-wake-lock` и оборачивает `navigator.wakeLock.request`, чтобы видеть выданные блокировки. Подмена браузера с отказами и скрытой страницей — у whoami (`wake-lock.spec.js`): это поведение ядра.
- **HTTP API**: `api.spec.js` — без страницы, только в проекте `desktop`.
- **Метка запросов**: `check-tag.spec.js` запускает тест ядра о метке ` EscapistCheck` в user agent на настройках игры (`packages/room-kit/docs/testing.md`, Против прода).
- **Сайт** (тесты ядра, `packages/room-kit/docs/testing.md`, Общие тесты ядра; их же запускают `landing.spec.js`, `room.spec.js` и `room-timers.spec.js`): `site.spec.js` — ничего с чужих сайтов, заголовки безопасности у каждого вида адреса (статические файлы — из `_headers` ядра, API и комнаты — из копии в Worker), версия в подвале, иконки, регистрация service worker, баннер обновления (подставной: выпуск в тесте не устроить); `not-found.spec.js` — страница 404 и адреса, которых у игры нет. Что `/_headers` и `/.assetsignore` не отдаются, обеспечивает wrangler: из кода игры этого не сломать, тест сторожит платформу.
- **Превью ссылки** (тесты ядра): `link-preview.spec.js` читает страницы так, как их читает бот мессенджера (ответ сервера, разобранный без скриптов): карточки двух страниц одинаковы, картинка — JPEG 1200×630 легче предела WhatsApp, `robots.txt` ничего не закрывает, `llms.txt` на месте. Что карточки называют адрес того самого сайта, проверяется только против развёрнутого сайта (`BASE_URL`): в разметке записан адрес прода. Только в проекте `desktop` — карточки это разметка.
- **Доступность**: `accessibility.spec.js` — axe (WCAG 2.1 AA) на главной, в лобби, на письме, на чтении, в окне всех историй (и с вопросом «Ещё раунд» в нём), на листе сыгранных раундов, на экране ожидания, в окнах и на баннере обновления; переходы цветов на время проверки выключены правилом в `style.css` страницы.
- **Журнал игры** в консоли теста: `await player.page.evaluate(() => localStorage.setItem('consequences-debug', 'on'))` и перезагрузка.
