## Project Overview
Web application to play Consequences, the parlour story game, remotely with friends and family. Players join a room by a 6-character code; in a round every player answers the same question on the sheet in front of them, nobody sees the answers before theirs and the sheets move on, eight questions in all, of one set the round draws (seven sets: the classic one — Who? / With whom? / When? / Where? / What were they doing? / How did it all end? / What did people say? / What is the moral? —, Incident, He and She, Fairy Tale, Detective Story, The News, Journey); at the end each player reads out the story that came to them. Adaptive UI works on desktop and mobile browsers.

- **Production:** https://story.escapist.club/ (Cloudflare Workers, free plan), from the first release (root `docs/release.md`)
- **Repository:** https://github.com/mikhail-e/parlour-games, folder `games/consequences/` — public, a showcase (root CLAUDE.md, Decisions)
- **Stack:** the same as every game on the kit: Cloudflare Workers + Durable Objects (one per room, `wrangler`), vanilla JavaScript + Bootstrap 5 (the kit's local copy), Jest and Playwright. No frontend framework and no bundler: the only build step copies the kit's files into `public/` (`npm run build`, run by wrangler itself).

## Commands
In this folder; from the repository root the npm scripts take `-w games/consequences` (`npm start -w games/consequences`). Installing the packages and the once-per-machine steps: root CLAUDE.md.
```bash
npm start                          # wrangler dev: copies the kit's files (npm run build), then the Worker, its rooms and the files on http://localhost:8788
npm test                           # The game's checks: ESLint, Jest, then Playwright (before a merge: npm test at the root, every game's)
npm run lint                       # ESLint only (any warning fails); npm run lint:fix fixes what it can
npx jest tests/game-logic.test.js  # Run a single Jest file (in this folder only: Jest's settings are in its package.json)
npm run test:e2e                   # Browser tests only (Playwright); :headed and :ui variants
npm run test:e2e:prod              # Browser tests against production (after a release)
```

### How it works
- **Rooms, entering, leaving and the players list are the kit's**, as in every game on it (`packages/room-kit/CLAUDE.md`: The room, The room with players, The Worker's frame, The players of a room, The landing page, The room page): a room per 6-character code, the HTTP API (`POST /api/create-game`, `POST /api/join-game`, `GET /game/:roomCode`, the socket `/ws/CODE`, `GET /api/version`), the player's ID and secret per browser, joining with the secret, the first-join order of the list, online and offline, ghosts after the kit's hour, the room's timers and storage, the security headers. **Who acts is the player the socket is registered for**, never an ID from the message
- **The round** (`game.round` in game-logic.js, with the model in its header): at the start every player of the list takes a seat in the list's order — offline ones too: a phone that slept in the lobby must not leave its owner out — with a blank sheet of eight questions (`QUESTION_COUNT`); at least two players (`startRound`). **The round's set of questions**: the round draws one of the sets (`QUESTION_SETS`, their names; their texts are the pages', `<set>Name`, `<set>Question1`–`8` and the round's headings in translations.js, `translations.test.js` keeps the two lists together) at random, never the room's last one (`game.lastQuestionSet`, kept as the round starts, so a round broken off counts; a room that is deleted forgets it — the owner's decisions), and every sheet of the round asks its questions (`round.questionSet`). A round an earlier version saved has none: `roundView` gives `classic`, the one list the game had before, so a round across a deploy goes on with the questions it started with. `step` 0–7 is a question, 8 the reading. At step s seat i holds sheet `(i − s) mod N` (`sheetAt`): sheet j starts at seat j, its last answer is written at seat `(j + 7) mod N` and it is read at `(j + 8) mod N` — the seat after, so for any N ≥ 2 nobody reads the sheet whose last answer is theirs. An answer is trimmed, never empty, at most 200 characters counted as a person counts them (`MAX_ANSWER_LENGTH`; longer is refused, not cut: the page holds the same limit), and stays as sent, with who wrote it (`by`) — while the step is on, its seat's player may take back an answer they wrote themselves (`takeBackAnswer`, «Change the answer»: the seat is blank again and the step waits for it; one written for them by another stays). A step ends when every sheet has its answer — a slow player online is waited for — and a short pause has passed (`STEP_PAUSE_MS`, five seconds, the owner's decision: whoever answered last has time to press «Change the answer»): `round.stepEndsAt` keeps when, so it survives the room's sleep; the room's one timer goes off for it too (`setAlarmAt` and `alarm` in worker/room.js), and `moveSheetsIfDue` makes `step + 1`, `takenBy` cleared. A take-back in the pause stops it, and the new answer starts a whole one. The Worker's var `STEP_PAUSE_MS` shortens it for the browser tests
- **Absent seats** (`isAbsent`): a seat whose player is offline or has left. A player who has answered this step and holds nothing takes an absent seat's blank sheet (`takeSheet`, "Answer for"); in the reading any player who holds nothing takes an absent seat's closed sheet ("Read for"). The first to ask gets it — the room takes its messages one at a time — and `takenBy` says who holds it. The sheet goes back on the table with "Put it back" (`returnSheet`), its answer or its opening, the taker leaving (the `forget` hook), and the taker's last page going (`releaseSheetsOf`, the room's part). A player back while another holds their sheet waits for the next step (or lets the reader read)
- **Leavers keep their seats**: a leaver of the round goes from `players` but stays in `seats`; the kit's snapshot (`recentlyLeft`) keeps their secret's hash, join time and — the game's hook — name and avatar, so the others see whose seat it is, and the same browser comes back to its seat and its place in the list without asking. Ghosts removed by the kit's timer leave the same way
- **The reading** (step 8): a player opens the sheet in front of their seat, or an absent seat's sheet they took (`openSheet`); `openedBy` says who opened which. Until every sheet is open a sheet's answers go only to who opened it (`sheetsOpenedBy`, for their page after a reload too); once the last opens, every story with who read it is everybody's to look at (`allStories`), each player going there by their own press. A story's title is its number in words, with the set's word for a story («История первая», «Сказка первая»: `<set>StoryTitle1`… in translations.js, one for each seat of the fullest room, `translations.test.js` keeps them). A story reads as one text: its answers in order with a line between them and no questions over them (the owner's decision), on the open sheet and in every story
- **A new round** (`newRound`): in the middle of a round or after every story — back to the lobby with the same players. The page asks first, in words of the round's phase (the owner's decision): while writing the sheets are lost, red as all that cannot be undone (`newRoundText`); from the reading on the stories stay in the history and another player may still be reading their sheet, so the question is in ink (`newRoundKeepsStories`). The room then sends everyone to the lobby; the round, the leavers' snapshots (their seats) and the waiting newcomers' requests go, and the room tells the newcomers' pages to join again (`endedJoinRequests`)
- **The room's history** (`historyRoundOf`, the model in game-logic.js's header): a round that reached the reading goes into it as `newRound` ends it, every sheet whole, even one nobody opened (the owner's decision: once the round is over there is no reading left to keep a secret for); a round ended while writing does not, and its answers never reach a page. Who read a story is kept by name, taken before the leavers' snapshots go: the history outlives them. The game keeps only the sets of its rounds (`game.historySets`, none in a game an earlier version saved); each round lies in the room's storage under its own key, `history:N` (N from 1), written once, in the same write as the game (`afterChange` with the key): the game is written after every move, and a history inside it would be written again with every answer. The kit's `deleteAll()` takes the keys with the room (worker/room.js). It lives as long as the room: every player of the room sees it, newcomers too
- **Socket events:** the room page's socket is the kit's `RoomSocket` on `/ws/CODE`, its room the kit's room with players: `join-room`, `ask-to-join` and `leave-game` are the kit's, and so are the sockets' roles (`player`, `waiting` — a newcomer's page hears nothing of the room). The game's moves (`MOVES` in worker/room.js), each carrying only what it needs, the acting player being the socket's: `start-round`; `write-answer` `{ text, for? }` — `for` is the absent seat's player whose sheet the sender holds; `take-back-answer` `{ step }` — the step the page shows; `take-sheet` `{ playerId }` and `return-sheet` `{ playerId }` — "Answer for" while writing, "Read for" while reading, and putting the sheet back; `open-sheet` `{ for? }`; `new-round`; `history-round` `{ number }` — a round of the room's history, 1 to the last: the room answers the sender's socket alone `history-round` `{ number, round }`, and saves nothing. A refused move answers its sender `error` with the rules' English text. The page sends them through the kit's `sendMove()`
- **`round-state`** `{ state, round, historySets }` (`roundView`, and the sets of the room's history) goes to every player socket after every change of the room while a round is on — a move, a page that joins or goes, a leaver, a ghost (the room's `afterChange`) — and with `round: null` when a new round takes the room back to the lobby. The kit tells the pages nothing when a player comes back online, so a seat's presence (`absent`: `offline` or `left`) is the round's. The players list's broadcasts (`player-joined`, `-reconnected`, `-left`) carry the round and the history's sets too (the `view` hook), and so does `game-state` (`serializeGame`). **The history's rounds themselves never go with them**: a page asks for the one it shows (`history-round`), so what a joining page gets does not grow with the rounds played. **The page redraws the whole round screen from it** — as whoami redraws its players list — never patching one seat
- **The answers are secrets until the reading**: `round-state` carries no answer's text until the last sheet is open, and then every story with who read it. While writing, an answer goes nowhere, its author's page included. An opened sheet's answers go only to the sockets of who opened it (`sheet` `{ sheet, answers }`), and again to their page when it joins after a reload (the room's `joinRoom`, after the kit's `game-state`); `tests/e2e/secret.spec.js` reads every message the pages get
- **A held sheet goes back on the table** when the holder's last page goes (the room's `onSocketGone`, before the kit marks them offline and saves) and when the room loads with a holder without a page (`reconcile`); a leaver's held sheets go with the kit's `forget` hook
- **The room page** (`game-room.js`, on the kit's `startRoomPage`) draws the whole screen from `currentGame` on every change: the lobby while `round` is null; while writing, the sheet's title — the round's set, the kit's `.sheet-title` (`#setTitle`), with whose sheet it is under it when it is an absent player's the player took (`#writingTitle`, a line, never a second title) —, the step and its eight marks, the sheet in front of the player with the answered questions folded (the questions, never the answers) and the question, the table; while reading, the player's sheet closed until tapped (`open-sheet`), the absent players' sheets they took, how many are open, «Every story» (`#showStories`, there from the start of the reading, off until every sheet is open), the table; once every sheet is open, «Another round» under «Every story» takes the place of «New round» under the table. **The window of every story** (`#storiesModal`, one Bootstrap window for both ways in, the owner's decision) shows one round of the room at a time: «Every story» opens it on the round being read, a row of the lobby's «Rounds played» (`#roundsCard`, the rounds by number with their sets, there in the lobby while the history has one) on its round. Its title is the shown round's set's («Все сказки»), the line under it «Round N of M»; «Previous» and «Next» lie under the last story, not pinned (the owner's pick), and show the round next to it from its first story, the focus on the window's title. The rounds it pages through are the history's, then the round being read once every sheet is open. Its state is the page's own (`storiesWindow`: the round shown, the question asked): a press opens it, so the last sheet to open changes nobody's screen, or its reader would never see it, and a reload goes back to the reading. A round of the history comes from the room when the window first needs it (`history-round`), and the one before it with it, so «Previous» need not wait; the page keeps them, as a round of the history never changes, and keeps the round being read when it ends (`keepEndedRound`): the window open on it goes on showing it without asking. The stories are drawn anew only when the round, its stories or the language change, so a reader's place and a «Copied!» stay. **The window stays open through the room's changes** (the owner's decision): another player's «Another round» leaves it on its round, now the history's; a round that starts adds the line «A new round has started» (`#newRoundStarted`) and the reader closes the window when they are done. «Another round» is in the window too, under the buttons, for the round being read only; its question comes inside the window, in the stories' place, with «Cancel» back to them (Bootstrap's windows do not stack: Gotchas). **The round's set speaks on the screen** (`sayOfSet`: the round's `questionSet`, `classic` for a round without one): the questions and the pleats are its, and the round's headings say its stories instead of "stories" — the table while writing («Сказку рассказывают»), the reading («Сказки готовы»), «Every story» and its window («Все сказки»), each story's title («Сказка первая») — the owner's decision: never two titles on one card, so the set's name is a title only while writing. A shared story begins with the set's name in capitals between two stars (`★ СКАЗКА ★`: a shared text is plain, bold is every messenger's own markup), then the answers and the invitation. The table shows each seat here or away (`offline`, `left`), its step done (in ink with a ✓) or not, who answers or reads for it, "Answer for" / "Read for" an absent seat to a player free to take it (answered at this step, holding nothing), and the newcomers waiting (`joinRequests`, the kit's `join-requested` and `join-request-closed`). **The answer form is never rebuilt**: it is in the markup and only shown, hidden and relabelled, so an answer being typed survives the others' moves and a language change; it is emptied when its sheet changes (the next step, another seat's sheet), and a sheet that comes to the player — the start, the next step, a reload, "Answer for", «Change the answer» — opens with the focus in the field. While they wait, the answer the player wrote shows under the pleats (`#sentBlock`, so a slip can be seen), and «Change the answer» (`#editAnswer`, only for an answer the player wrote, while they wait) puts it back into the field: both from what this tab sent (`sentAnswer` in sessionStorage, cleared in the lobby), as the room never sends an answer's text back before the stories, so another tab of the player's shows no text. The page keeps the answers of the sheets its player opened (`sheet`), cleared when a socket joins (`game-state`: they come again after it). A move another player beat (two took one sheet, two pressed Start) is ignored (`LOST_RACES`): the `round-state` that follows shows how things are. The screen is kept awake while the round is on, until this page opens every story (`storiesSeen`; the kit's `keepScreenAwake`)
- **The kit and the game:** what knows nothing of the game is the kit's; the game's part is `worker/room.js` (its moves), `game-logic.js` (its rules and its hooks for the players list), the pages' markup, `style.css` (its own look), `game-room.js` (its field and events) and its brand. When unsure where code goes, it goes into the game's part

## Rules (important!)
1. **Bump the icon cache version in `CACHE_NAME`** (public/sw.js, `consequences-game-v2` → `v3`) **when you change the icons** (drawn in `scripts/icon.html`, taken by `npm run icons`). Only icons are cached, so HTML/CSS/JS changes reach players without it. This is not the app version — that one is in package.json
2. **No code duplication across files** — code every game shares goes to the kit (`packages/room-kit/`)
3. **Update tests whenever logic changes**: a game rule → Jest with `game-logic.js`; what the player sees or does → a browser test in `tests/e2e/` (the kit's `docs/testing.md`). Run `npm test` before committing
4. **Localize all UI text** — every user-facing string of the game needs both `en` and `ru` entries in `public/js/translations.js` (the kit's rule and its `data-i18n*` attributes: `packages/room-kit/CLAUDE.md`, Translations); a text the kit already has is the kit's, not repeated. An error the server sent is shown through `serverErrorText()`; `serverErrors` holds the Russian copies of the game's own errors (game-logic.js, worker/), keyed by the English text. `tests/translations.test.js` fails if a key is in one language only, the placeholders differ, a kit's text is repeated, or a text the server sends has no copy (the kit's `translationProblems`). Rewording a server error means rewording its key too, and `LOST_RACES` in game-room.js compares some of them itself
5. **Never build DOM from user data with `innerHTML`** — player names and answers go through `textContent`, avatars through the kit's `renderAvatar()`
6. **Debug output goes through `debugLog()`** — the kit's rule (`packages/room-kit/CLAUDE.md`, Rules); here it prints after `localStorage.setItem('consequences-debug', 'on')` and a reload
7. **The pages share names through plain `<script>` files** — the kit's rule; the game's scripts take the kit's names and give the kit `APP_STORAGE_PREFIX` (config.js), `translations` and `serverErrors` (translations.js); `tests/shared-names.test.js` checks the game's scripts and the kit's together
8. **Only the game's own code runs on its pages** — the kit's rule: no `style="..."` or `on...="..."` attributes; `tests/code-structure.test.js` checks the game's pages and scripts, the browser tests' guard any other blocked code

## Gotchas
- **The answer's length limit (200) and the fewest players of a round (2) exist twice** — the server's in `game-logic.js` and `public/js/utils.js` for the browser (a browser script cannot `require()` a Node module); `tests/input-limits.test.js` fails if they drift apart. The limit is counted by character, not UTF-16 code unit, like a name: an emoji counts as one
- **The list's order is the order of first joins** (the kit's): Jest tests that join several players advance fake time between the joins, as people never join in one millisecond — with equal join times a returning leaver would not get their place back
- `game-logic.js` must stay free of Cloudflare imports (CommonJS) so Jest tests it in Node; its functions take a `Map` of games, and a room passes a Map of its one game
- **The sign** ("CONSEQUENCES", in whoami's frame) is an inline `<svg class="brand-sign">` in three deliberate copies — index.html and game.html (the `h1`), 404.html (a `<p>`: its `h1` is "Page not found"); `tests/brand-sign.test.js` keeps them equal (the kit's `brandSignProblems`). It is a logo: English in both languages (Oswald, its face, has no Cyrillic), `aria-label="Consequences"`, and its `h1` carries **no** `data-i18n` — the Russian name, «Чепуха», is in the subtitle and the tab's title. Its fonts come from style.css by class (a `<style>` inside the SVG is inline code the CSP blocks); the name's fill is written in the markup, the same color as `--accent`. Oswald has a `preload` in the three pages
- **The game's color is bottle green**: style.css sets the kit's `--accent`, `--accent-tint`, `--curtain-top` and `--curtain-bottom` on its `:root` (the kit's CLAUDE.md, The playbill look); red stays the kit's, for what cannot be undone. The app's color `#1b4a36` (the top of the curtain) is written in the three pages' `theme-color` and in the manifest (`tests/manifest.test.js` keeps them equal to `--curtain-top`)
- **A step's pause is counted twice**: Cloudflare now and then runs an alarm many seconds late so a room that is awake also counts the pause with a plain `setTimeout` (`countStepPause`, `worker/room.js`). The alarm stays: only it survives the room's sleep. Whichever comes first moves the sheets, and the other finds nothing due
- **A shared story carries the site's address inside its text**, not in the share sheet's `url`: some apps keep only one of the two (`shareStory`, `game-room.js`; the sheet and its fallback are the kit's `shareOrCopy`)
- **The pleats' broken edges are a `clip-path`** (`--fold-shift` in style.css, the owner's pick from a page of variants), on the sheet being written. A pleat is counted from the last (`:nth-last-child`), which always ends level with the open part, so the open part is a step narrower, and whole while there are no pleats. A clip cuts a `box-shadow` and shows the element behind it, so `.sheet--pleated` has no paper of its own and casts a `filter: drop-shadow`; the stories' `.sheet` stays a plain rectangle
- **A closed sheet is a sealed envelope** (the owner's pick from a page of variants, on the way of whoami's): the wax is `public/img/seal.svg` in the game's color, pressed with the app icon's quill, a deliberate copy (an SVG file cannot take a drawing from another file): `tests/seal.test.js` keeps the two equal, so a new drawing of the icon's quill goes into both. The flap's point is 8px below the seal's center on purpose (`--flap-point`, the owner's pick by eye): the wax hides it and the eye carries the lines on to a meeting above it, so an exact match looks too high
- **`hidden` loses to Bootstrap's display utilities**: `.d-grid`, `.d-flex` and the like set `display` with `!important`, and so does Bootstrap's `[hidden]` — the utility comes later and wins. An element the script shows and hides (`hidden`) never carries one: put the utility on a wrapper that always shows, or use `w-100` on the button itself (`#giveSheetBack`)
- **Bootstrap's windows do not open one over another**: a second window over an open one breaks the first's focus and backdrop, so the window of every story asks its «Another round» inside itself (`#windowNewRoundText`, `#windowNewRoundButtons`), never through `#newRoundModal`. An open window keeps the focus inside itself: a sheet that comes to the player while it is open leaves the answer field alone, and the field gets the focus when the window closes (`focusAnswerField`); the kit's old way of copying puts its field inside the window (the kit's CLAUDE.md, The invitation)
- **The answer is counted by characters in the page too**: no `maxlength` on the field (it counts UTF-16 units, an emoji two); the counter shows `n/200` as a person counts, and over the limit the button is off. An empty answer is not sent: the field keeps the focus
- **A computer and a phone send differently** (one test, `(hover: hover) and (pointer: fine)`, in `style.css` and `game-room.js`). On a computer Enter sends the answer through the button's own `sendAnswer`, so the same checks hold for both (empty, over the limit, already sending), Shift + Enter breaks a line, a hint under the field says so, and the send button is the main one under the field; an Enter that ends a word of an input method is not one (`isComposing`, Safari's key code 229). On a phone (no mouse) Enter breaks a line and the send button is a square in the game's color at the field's right, level with its bottom, where the keyboard does not cover it: the form becomes a grid, the same button in the same markup, its label kept for a screen reader. The label is a span of its own: `data-i18n` replaces an element's text and would take the plane with it. The story keeps a broken line (`white-space: pre-line`)
- **The link preview card is written twice, in English** — `index.html` and `game.html` (without `og:url`: one file serves every room) carry the same `og:`/`twitter:` tags, a bot reads them without running the page (`docs/publishing.md`); `tests/e2e/link-preview.spec.js` keeps them equal. The addresses in them are absolute, the production one (`docs/publishing.md`, where the address is written)
- **The service worker caches icons and nothing else** — the kit's logic (`packages/room-kit/CLAUDE.md`, PWA); `public/sw.js` holds only the cache name and the icons, and `tests/service-worker.test.js` fails if anything else is added to the list. **Any change to sw.js, even a comment, is a new worker** (and so is a change to the kit's `service-worker.js`): every open page shows the "Update available" banner, so edit it only for a real reason
- **`public/` is uploaded as it is** (the kit's Gotchas): `public/.assetsignore` names `.DS_Store`; `_headers` and `.assetsignore` themselves are never served (`not-found.spec.js` checks)
- **`npm start` listens on 8788, its inspector on 9238** (`dev` in wrangler.jsonc), the browser tests on 3200 and 3201 (inspectors 9232, 9233): whoami's are 8787 with wrangler's default 9229, 3100 and 3101 (9230, 9231), so both games can run side by side, their tests too. Without its own inspector port the second `npm start` would take 9230 and stop whoami's tests
