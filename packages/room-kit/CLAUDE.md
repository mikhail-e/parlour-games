# CLAUDE.md - room-kit

The shared kit of the parlour games with rooms: one npm workspace package, `@parlour-games/room-kit`, that every game takes from instead of copying. The repository's layout, commands, git flow and decisions are in the root `CLAUDE.md`; a game's own rules in its `CLAUDE.md`, which imports this file, so the rules here hold for every game on the kit. Paths here are from this folder, `packages/room-kit/`.

## What goes here
- **The kit knows no game**: no event names, no texts of a game, no rules, no layout of a game's pages. Code that does is the game's. When unsure where code goes, it goes into the game
- **Only what a game already uses**: the kit grows when a game needs something shared, not in advance for a game that does not exist yet
- **No version of its own**: the kit goes out with the games' releases (each game's `/api/version` is the game's); a change to the kit is a change to every game on it, so `npm test` at the root, every game's checks, runs before every merge

## Commands
From the repository root with `-w packages/room-kit`, or in this folder.
```bash
npm test                           # The kit's checks: ESLint, then Jest
npm run lint                       # ESLint only (any warning fails); npm run lint:fix fixes what it can
```

## How a game uses it
- The game names the kit in its `package.json`: `"dependencies": { "@parlour-games/room-kit": "*" }`. npm links the workspace package into the root's `node_modules` (no version needed), and the game imports its files by path, `@parlour-games/room-kit/<file>`. The package has no `exports` map on purpose: every file is reachable by its path, for Node, Jest and wrangler alike
- **The copy in a game's public/**: Cloudflare serves a Worker's static files from one folder, the game's `public/`, so the kit's `public/` is copied over it — `public/_headers` and `public/kit/` (pages link `/kit/vendor/bootstrap/…`, `/kit/fonts/fonts.css`). The copies are not in git (`.gitignore`: `games/*/public/kit/`, `games/*/public/_headers`) and are edited in the kit only: the next copy overwrites a game's change. The game's `build` script is `room-kit-copy-public public`; its `wrangler.jsonc` runs it before serving or uploading (`"build": { "command": "npm run build -w <the game's package name>", "watch_dir": "../../packages/room-kit/public" }`), so `npm start` and the browser tests' servers always start on a fresh copy, and `npm start` copies again when a file of the kit changes. The command names the game, not its path: wrangler runs it in the folder it was started in — the game's for `npm start` and the tests, the root's for Workers Builds. In Workers Builds the copy runs twice: its Build command copies, then `wrangler deploy` runs `build` again and writes nothing, the files being in place. The Build command stays: Cloudflare documents that Workers Builds does not run wrangler's `build` (root `docs/release.md`)
- **The copy is safe to run twice at once** (the browser tests start two `wrangler dev`): a file is written only when it differs, through a temporary file renamed into place, so a server never reads half a file; what the kit no longer has leaves the game's `public/kit/`, and nothing else of the game's `public/` is touched (`tests/copy-public.test.js`)
- **Checks of page code** (`checks.js`, for Jest): `sharedNameProblems([folders])` and `inlineCodeProblems([folders])` return what is wrong, an empty list when nothing is; a game's tests call them with its folders and `KIT_SCRIPTS` (whoami: `shared-names.test.js`, `code-structure.test.js`)
- **Playwright**: a game's `playwright.config.js` is `defineConfig(roomKitPlaywright({ port, servers }))` (`playwright.js`): the kit gives the projects — a phone (Pixel 7) and a desktop, Chromium only —, `use` (reduced motion, the service worker on, traces off), the timeouts for a run against production (`BASE_URL`) and a `wrangler dev` per server (its own port and inspector port, the rooms' storage in a temporary folder, `vars` for the Worker; never reused: a server left running would test yesterday's code); the game gives its ports. `e2e.js` gives `test` and `expect`: `newPlayer(name, { locale })` opens a browser context of its own on the project's device, and the guard fails the test on a page's JavaScript error, `console.error` (a Content Security Policy block among them, named by an init script), or a dialog it did not expect (`player.expectDialog`, `player.allowConsoleError`); the one it lets pass is the test tool's own — a trace Playwright records fetches a `blob:` image. A game's `tests/e2e/helpers.js` passes on that `test` and the kit's `e2e-helpers.js`, with its own helpers: `pageTexts(translations.js)` gives `text` and `serverErrorText` (the game's texts on top of the kit's, as on the page), the rest act through the kit's pages by its markup's ids and the player cards (`createRoom`, `joinRoom`, `askToJoin`, `leaveGame`, `roomWith`, `playerCard`, `stubShare`, `holdRoomJoin`, `countSentEvents`, `pngFile`…; `docs/testing.md`)
- **ESLint**: a game's `eslint.config.mjs` spreads `roomKitEslint({ ignores })` (`eslint.mjs`) and adds blocks of its own (whoami: `game-logic.js`), with `sharedRules` for them. `ignores` is the config's own: a game skips its copy of the kit's files, the kit only the third-party code among them

### The room
`worker/room-base.js`: the base of every room — a game's room builds on it through the room with players (`GameRoom`, below) —, one Durable Object per room code, found by the code (`env.ROOMS.getByName(code)`). Cloudflare puts a room to sleep between messages and may take it out of memory at any moment (the WebSocket Hibernation API: a sleeping room costs nothing), so **nothing lives only in memory**: what the room knows of a socket lives in the socket itself — its attachment (`getInfo` / `setInfo`), which survives the sleep; the room with players keeps there whose the socket is (a player's or a waiting newcomer's role) — and everything else in the room's storage, which the game's room loads as it wakes.
- `fetch` accepts a page's socket (anything else: 426); messages are JSON `{ event, data }`. A message that is not that gets no answer, and a handler that fails cannot break the room: `onEvent(ws, event, data)` is the game's, `onEventError` answers a failure the game's way, `onSocketGone(ws, info)` hears a socket that closed, broke or went silent — once, with what the room knew of it
- `send(ws, event, data)` to one socket (a socket that has just gone takes nothing, and that is no error); `broadcast(event, data, { only, except })` to every socket whose info passes `only`, the sender included unless it is `except`; `sockets(filter)` — the open ones
- **Connection check**: a page pings, and the room answers `pong` without waking (an auto-response). While sockets are open, the game's timer calls `sweepSilentSockets()` every `SWEEP_EVERY_MS` (a minute): a socket not heard for `SOCKET_SILENCE_MS` (2 minutes) counts gone — a phone asleep with its socket open. The ping's time is asked of the runtime; a socket that never pinged counts from its connection
- `setAlarmAt(times)` — the room's one timer at the earliest of the times given (none: no timer); which times, is the game's

### The room with players
`worker/game-room.js`: `GameRoom` extends `RoomBase` with what every game's room does with its players; a game's room `extends GameRoom` (whoami: `worker/room.js`) and calls `super(ctx, env, { rules, moves })`. It keeps its one game in its storage under its code and holds it in a Map of that one game (the players list's functions take a Map, The players of a room).
- **What the game gives**: `rules` — the functions `roomPlayers()` gave with the game's hooks (`createGame`, `addPlayerToGame`, `removePlayerFromGame`, `removeStaleDisconnectedPlayers`, `playersView`) and `serializeGame(game)`, the game as a player's page gets it in `game-state` (never a secret's hash); `moves` — event name → the name of the room's method for it, `(ws, data, { gameId, playerId })`. A move's handler tells the pages itself (`broadcast(…, { only: isPlayer })`) and ends with `afterChange()`. `gameState(game)` may be overridden for what a joining page gets
- **The storage**: the room loads its game as it wakes, saves it after every change (`afterChange()`: the game, `emptySince` — when the last page of a player closed —, and the timer for what is due next: the room's end, a ghost, the next sweep of silent sockets). A room without a game keeps nothing. A room that went down with its sockets heard none of them close: as it loads (`reconcile()`), a player marked online without a socket goes offline, a request without a waiting page goes. The timer deletes a room nobody had open for the empty-room time, removes ghosts while somebody plays, and sweeps silent sockets; with nothing changed it writes nothing. The times come from the players list, or from the Worker's vars `ROOM_EMPTY_MS` and `GHOST_MS` (a game's browser tests shorten them)
- **The HTTP side** (the Worker's room addresses call it): `create(code)` — a new game, only in a room without one; `hasGame()`; `join({ playerName, avatar, playerId, playerSecret })` — the answer's status and body: "Game not found" before the secret is asked for (a page left open across a deploy, without one, learns the room is gone), "Missing required fields" without a secret, `{ success: false, waitingForApproval: true }` with status 200 for a newcomer to a round, otherwise the players list's answer; a join broadcasts `player-joined` (a new player) or `player-reconnected` with the players list (`playersView`). A join does not make a player online
- **The sockets' roles** live in their attachments: `{ role: 'player', playerId }` after `join-room`, `{ role: 'waiting', playerId }` after `ask-to-join`, no role otherwise (filters `isPlayer`, `isPlayerOf(id)`, `isWaitingFor(id)`; `withoutRole`). `join-room` with the player's ID and secret (`checkPlayerSecret`) gives the role, marks the player online and sends `game-state`; a page whose player is no longer in the room — left in another tab, the room gone — is answered `player-left` for itself (`{ playerId, gameDeleted }`), or it would stay in a room it never hears. The first page of a player back after a time without any restarts the ghosts' clocks. A socket is one page and one player; two tabs are one player, and a player goes offline only with their last socket (`player-disconnected` to the others)
- **Moves**: a move is taken only from a socket with the role `player`, and **the player who acts is the socket's, never an ID from the message**; a socket without the role gets "You are not in this game" and hears nothing of the room. A message that is not JSON `{ event: string }`, or an event that is neither `join-room`, `ask-to-join`, `leave-game` nor a move of the game, gets no answer; a handler that fails answers "Something went wrong, please try again". Broadcasts reach every player socket, the sender's included
- **Waiting pages**: a newcomer's page sends `ask-to-join` (ID, secret, name, avatar) over its socket; the request is recorded (`requestToJoin`), the socket gets the role `waiting` (never `player`: it acts for nobody and hears nothing of the room) and the players `join-requested`. Whoever may simply join is answered `join-request-ended` `{ outcome: 'retry' }`. A request goes with the newcomer's last waiting page (the players hear `join-request-closed` `{ outcome: 'withdrawn' }`); a page that reconnects asks again. `endJoinRequests(ids, outcome)` ends requests for their pages: `'retry'` — the page joins again and follows the answer (let in, the lobby, a room that is gone), `'declined'` — it goes home. Which ends there are is the game's (whoami: a player lets the newcomer in or turns them away, a restart); the room's end and the last player's leaving end them with `'retry'`
- **Leaving** (`leave-game`, the kit's move): a player leaves only themselves, in all their tabs at once. `player-left` (`{ playerId, playerName, …playersView, gameDeleted }`) goes out BEFORE the leaver's sockets lose their role, so the leaver's own page hears it and goes home; a ghost removed by the timer is announced the same way. The last player out deletes the game and the room's storage (the old link leads home)
- **The log**: Workers Logs are the owner's to read; a value from a request goes there through `forLog()` (short; a photo is marked, a secret never written)

### The Worker's frame
`worker/http.js`: a game's `worker/index.js` is `export default gameWorker({ route, version: pkg.version })` plus its room classes. `route(request, env, { method, pathname })` answers the game's addresses, or nothing for an address that is not the game's. The frame answers `GET /api/version` with the game's version (its package.json), a HEAD as the GET it asks about without the body, an address nothing answers with the game's `public/404.html` and status 404, and a failure with `{ success: false }`, status 500 — JSON the page can read, never Cloudflare's error page. It puts the security headers on every answer but an accepted socket's (`withSecurityHeaders`; `notFound` is exported too). Which addresses reach the Worker at all is the game's `run_worker_first` in wrangler.jsonc: the static files are served without it, and cost nothing of the day's request limit
- **The addresses of a game with rooms** (`roomRoutes`, a game's `route` or part of it; its rooms bound as `ROOMS`, a class on `GameRoom`; its room page `public/game.html`): `POST /api/create-game` — the Worker picks a code (`generateRoomCode`) and the room takes the game only when it has none, a taken code is tried again; `POST /api/join-game` — a body over 64 KB is refused with 413 (the largest join carries one photo avatar), "Missing required fields" without a code, name or avatar, and the room gets the join's fields only, each a text or nothing, so nothing nested reaches it; `GET /game/CODE` — the code's format first (a code that is no room code never reaches a room: random addresses would create rooms), then the room page when the room has a game, or a redirect to `/?error=room-not-found`; `GET /ws/CODE` — the room page's socket, to its room. Codes typed in lower case are the same room. A room asked about but without a game writes nothing

### Room codes and player IDs
`shared/identity.js`, CommonJS (a game's rules require it, Node's `crypto` comes through `nodejs_compat`): a room code is 6 characters of `A-Z0-9` (`generateRoomCode` takes them from the cryptographic generator — the code is all that lets a stranger into a room; `isValidRoomCode`); a player ID is a UUID, and so is a player's secret (`PLAYER_ID_PATTERN`, `isValidPlayerId`; keep the pattern on one line: its browser copy is compared with it); the server keeps a hash of a secret, never the secret itself (`hashSecret`). whoami's `game-logic.js` exports them on under their own names

### The players of a room
`shared/players.js`, CommonJS like `identity.js`: the rules of a room's players, the same in every game, with no Cloudflare in them (Jest tests them in Node; `tests/players.test.js` on a game that keeps nothing of its own). It works on the game object the room keeps, on these fields: `players` (each with `id`, `name`, `avatar`, `isConnected`, `disconnectedAt`, `joinedAt`), `secrets` (player ID → the hash of their secret; never sent to a page), `recentlyLeft` (player ID → a leaver's snapshot), `joinRequests` (player ID → a waiting newcomer), `state`, `created`, `lastActivityAt`. A game keeps its own fields next to them (whoami: `characters`, `revealedPlayers`). Its functions take a `Map` of games, and a room passes a Map of its one game
- **Two states**: `'waiting'` — the lobby, anybody may join; `'started'` — a round is on: it takes back its players and its leavers, and a newcomer gets `{ success: false, waitingForApproval: true }` (not an error: their page waits) and asks over its socket (`requestToJoin`). What ends a newcomer's wait is the game's (whoami: a player lets them in or turns them away; a restart). A request lives as long as the newcomer's waiting pages (`withdrawJoinRequest`); one per browser, a second tab waits on the same one. Players and waiting newcomers together are at most 12 (`MAX_PLAYERS`, `isRoomFull`); a leaver returning to the round does not wait in line, so letting a newcomer in checks the seats once more
- **Joining with the secret**: the first join with a secret records its hash; after that, joining as this player — a reload, a second tab, a return to the round — needs the same secret ("This player is playing in another browser"), and a socket acts for a player only with it (`checkPlayerSecret`). Players are matched by ID only, never by name: two players may have one name
- **A leaver of a round** (`removePlayerFromGame` while `'started'`) leaves a snapshot in `recentlyLeft` — the hash of their secret, their join time, and what the game keeps of them — and the same browser comes back to the same place without asking anybody. A leaver of the lobby is simply gone. The last player out deletes the game, and the waiting newcomers' requests end with it (`endedJoinRequests`). A game clears the snapshots when its round ends
- **The list's order** is the order of first joins (`joinedAt`, `sortPlayersByJoinTime` after every add), the same on every page: pages never sort it. A returning leaver gets their old place back; a lobby rejoin goes to the end
- **Online and offline**: a player is online only once a page of theirs has joined the room's socket (`markPlayerConnected`), and offline when their last page goes (`markPlayerDisconnected`); an HTTP join does neither, so a player whose room page never opens becomes a ghost instead of staying online forever. A player offline for over an hour (`MAX_DISCONNECTED_MS`, the owner's decision: a phone that sleeps through a break keeps its place) is removed as a "ghost" (`removeStaleDisconnectedPlayers`, as if they had left) — **only while a page of a player is open**: a group whose phones all slept through a break finds its room as it left it, and the first page back gives every player still offline a fresh hour (`restartGhostClocks`) — otherwise the first one back after a long gap would see the others removed. A ghost is usually the same person back under a new ID (cleared storage, a messenger's browser, an installed app); what it costs in the lobby is the game's
- **The room's timers** (`roomAlarmTime`): with no page of a player open, the room goes 2 hours after the last one closed (`ROOM_EMPTY_MS`, the owner's decision: a group that took a long break comes back to its room; a room nobody ever opened goes the same way); with a page open, the earliest ghost is due. A room passes shorter times for its tests (whoami: `ROOM_EMPTY_MS` and `GHOST_MS` vars)
- **The game's hooks**: `roomPlayers({ fields, newPlayer, snapshot, restore, forget, view })` gives the functions that touch the game's own fields — `createGame`, `addPlayerToGame`, `addNewPlayer`, `removePlayerFromGame`, `removeStaleDisconnectedPlayers`; each hook may be left out. `fields()` — the game's fields of a new game; `newPlayer(game, snapshot)` — its fields of a player coming into the list (whoami: a sticker color, a returning leaver's own if free); `snapshot(game, player)` — what it keeps of a leaver of the round; `restore(game, player, snapshot)` — gives it back; `forget(game, playerId)` — drops it as the player leaves; `view(game)` — its part of what the pages get with the players list (a join's answer, a removal). The rest are plain exports
- **The room's storage**: `gameToStorage` / `gameFromStorage` keep the game as it is — every field, the game's own included, Maps, Sets and Dates tagged — so a field added later is kept without a change there. **The stored form does not change**: a room asleep wakes on whatever code is deployed and reads what an earlier version wrote (whoami's `tests/stored-round.test.js` holds a round an earlier version saved)
- **Limits**: a name is at most 128 characters, counted as a person counts them (an emoji is one), trimmed, never empty (`sanitizePlayerName`); an avatar is an emoji (at most 10 UTF-16 code units) or a small photo — a `data:image/(png|jpeg|webp);base64,…` URL of at most 32 KB (`isCustomAvatar`, `CUSTOM_AVATAR_PATTERN`, `MAX_CUSTOM_AVATAR_LENGTH`; never loosen the anchored pattern: a page shows the photo as an image). The browser has a copy of these limits (`public/kit/js/limits.js`, kept equal by `tests/limits.test.js`); keep each value on one line for that comparison
- **Errors** are English texts (`error: '...'`), with their Russian copies in the kit (Translations)

### The page scripts
Classic `<script>` files in `public/kit/js/`, no modules and no bundler, served at `/kit/js/…`. A top-level name of one is visible to the scripts loaded after it, so a page loads them in this order: in `<head>` the game's `config.js` (`APP_STORAGE_PREFIX`), the kit's `app.js`, the game's `translations.js` (`translations`, `serverErrors`), the kit's `i18n.js`, `limits.js` and `notify.js`, the game's own shared script if it has one (whoami: `utils.js`); at the end of `<body>` Bootstrap, the kit's `pwa.js`, then the page's own: on the landing page the kit's `landing.js`; on the room page the kit's `room-socket.js`, `wake-lock.js`, `invite.js`, `room-page.js` and last the game's room script, which hands the kit its part (`startRoomPage`, The room page). Those three names are what a game gives the kit; everything else goes the other way
- `app.js` — `debugLog`, `AppStorage` (localStorage and sessionStorage with JSON, a failure logged, never thrown; not named Storage, the browser's own name), `PLAYER_ID`, `PLAYER_SECRET`, and the version at the bottom of the page (`showAppVersion()`: every `[data-app-version]` element gets `v<version>` from `/api/version`)
- `limits.js` — `MAX_NAME_LENGTH` and `isCustomAvatar` (the photo avatar's check): the browser's copy of the players list's limits (The players of a room), so a page never sends what the server would cut or refuse
- `notify.js` — `showError` and `showInfo` (a dismissible alert at the top of the page's `.container`, before its first `.game-card`), `showNotification` (`.notification`, pinned to the screen, gone by itself), `handleApiError` (a request that got no answer at all: `connectionError`); a message always goes in as text, never as HTML
- **The game's keys in localStorage**: `<prefix>-debug`, `<prefix>-player-secret`, `<prefix>-language`, `<prefix>-player-name` and `<prefix>-player-avatar` (the landing page's last name and avatar), and the ID under `playerId` in every game (each game has its own address, and so its own localStorage). They are the players' saved data: a game never changes its prefix (whoami's is `whoami`, the keys it always had; `saved-browser.spec.js` there checks them)

### The player in the browser
One UUID per browser, `PLAYER_ID`, and a second one, the secret, `PLAYER_SECRET`: the ID is public (every page in a room sees the players list), the secret goes only to the server and proves that this browser is that player (a game's server records its hash: `shared/identity.js`). Both come from the cryptographic generator (`crypto.randomUUID()` would be shorter, but a browser offers it only on https and localhost, not on a phone that opens the game at the computer's plain-http address). **A stored ID that is not a valid UUID is regenerated on load** (`PLAYER_ID_PATTERN`): the server silently replaces non-UUID IDs, which would otherwise duplicate the player on every page load. The pattern exists twice — `app.js` and `shared/identity.js` — and `tests/player-id-pattern.test.js` keeps the two equal

### The page's socket
`RoomSocket` (`room-socket.js`): `new RoomSocket('/ws/CODE', { log: debugLog })` connects at once to the room (`worker/room-base.js`); `on(event, handler)`, `once`, `off`; `'connect'` on every opening, `'disconnect'` on every close of an open connection, any other event is one the room sends; `emit(event, data)`; `disconnect()` for good; `ws` — the current WebSocket (tests close it to drop the connection). Messages are JSON `{ event, data }`. **Connection check**: the page pings its room every 25 seconds and the room answers `pong` without waking; a page that has heard nothing for a minute and a half takes its connection for dead and connects a new one (more than a minute: a hidden desktop tab gets its timers once a minute; less than the room's 2 minutes), and a page coming back on screen pings at once and reconnects if no answer comes in 5 seconds. Reconnects wait 1 s, doubling up to 5 s, plus a random part

### The landing page
`landing.js`: a game's landing page — the player's name and avatar, creating a room and joining one. The markup is the game's (its `index.html`, its look); the script finds these parts by their ids, and a game's browser tests check that it works:
- `#playerForm` — submitting it joins the room whose code is in `#roomCode`, or creates one when the code is empty. The avatars sit inside the form, so **any other `<button>` in it needs `type="button"`**, or pressing it joins a game
- `#playerName` — its `maxLength` comes from `MAX_NAME_LENGTH`, its value from the last name used
- `#avatarSelector` — the script fills it with 12 tiles `.avatar-option` (the chosen one `.selected`, its value in the hidden input `#selectedAvatar`), dealt at random from the pool of emoji in `landing.js` (the server needs no pool: it checks only that an avatar is short); `#shuffleAvatars` deals 12 others, `#uploadAvatar` opens the hidden file input `#avatarFileInput`. The two buttons stay outside the grid, so a new deal keeps them and their focus
- `#roomCode` with its `label[for="roomCode"]`, `#joinBtn` (enabled with 6 characters typed), `#createNewGame` (disabled while a code is typed)
- **A photo avatar** is shrunk in the browser to a small square JPEG data URL that passes `isCustomAvatar` (decoded through an `<img>`, which applies a phone photo's rotation; lower qualities until it fits; failures are the texts `avatarNotImage`, `avatarReadFailed`, `avatarTooLarge`), pinned as the first tile through new deals, and shown only through `img.src`, never `innerHTML`
- **Remembered**: the name and avatar of the last create or join (`<prefix>-player-name`, `<prefix>-player-avatar`); the saved avatar comes first in the grid, so it is the chosen one, unless it is neither in the pool nor a valid photo. `?join=CODE` fills in the code (a room's link, a leaver's way home), `?error=room-not-found` and `?error=join-declined` say why the player is back
- Create and join go through the room addresses (`POST /api/create-game`, `/api/join-game`), then to the room page; the tab carries the name, avatar and room code there in sessionStorage (`playerData`), the ID and secret are the browser's

### The room page
`room-page.js`: what every game's room page does with its room. The game's room script calls `startRoomPage({ render, events, setUp, onGameState, cancelEdits, afterError, ignoreError })` as it loads (comments in `room-page.js`) and draws its own field from `currentGame`; it moves through `sendMove(event, data)`, which holds a move until the socket is in the room — after a reconnect the new socket joins only once the HTTP join is back. The markup is the game's `game.html`:
- **Entering**: the room code from the address (`/game/CODE`, read in upper case), the tab's `playerData` — a tab without it (a link opened anew) goes to the landing page with the code ready —, the HTTP join, then the socket's `join-room`; every `connect` enters again. `currentGame` is the server's picture — `game-state`, then the players list and the game's fields from `player-joined`, `-reconnected` and `-left` —, `currentPlayer` the player as the server keeps them; each change calls `render()`, and so does a change of language
- **Another player left**: `cancelEdits()`, `render()` and the notification `playerLeftNotification`. A socket's `error` is shown in the page's language after `afterError()`, unless `ignoreError(error)`
- **The waiting screen**: a newcomer to a round sees `#waitingSheet` (with `#waitingAvatar` and `#waitingName`; `hidden` until then), the body gets `.waiting-for-admission` (the game's style hides the room with it), the screen stays awake (a sleeping phone loses its socket, and the request with it), and the page asks over its socket; `join-request-ended` enters again (`retry`) or goes home (`declined`: `/?join=CODE&error=join-declined`). `#cancelJoinRequest` gives up: the socket closes first, which withdraws the request at once, then the page goes home
- **Leaving**: `#leaveGame` opens the Bootstrap window `#leaveModal`, its `#confirmLeave` sends `leave-game`; the page goes home on the room's `player-left` for itself (`/?join=CODE`, or `/` when the room was deleted), or after 2 seconds anyway, unless the room answered with an error
- **The invitation** (`invite.js`, set up by the room page): the code goes into `#roomCode`, the room's link into the field `#shareLink`. Copy Link (`#copyLink` in the lobby, `#gameCopyLink` in a round) writes the link to the clipboard; a page the clipboard is closed to (plain http, as a phone on the home network) selects `#shareLink` and copies the old way. Share (`#shareButton`, `#gameShareButton`) opens the system's share sheet with the game's `title` and `shareText`: no `await` before `navigator.share` (iOS refuses a sheet not opened right in the click), closing the sheet is silent, a browser without Web Share copies instead. A page has whichever of the buttons it wants. "✅ Copied!" replaces the button's text, its `data-i18n` span with it: until a reload that button's label no longer follows a change of language
- `renderAvatar(element, avatar)` — a photo as an `<img>` behind `isCustomAvatar`, an emoji as text

### Translations
`i18n.js`: the page's language is the player's choice (`<prefix>-language`) or the browser's, English for a language the game does not have; the texts are the game's (`translations`) on top of the kit's own (`KIT_TEXTS`: the texts of the shared parts — the landing form, entering, leaving, the waiting screen, the invitation, notifications, the update banner, the 404 page —, under the keys whoami always had; the markup is a game's, its words the kit's; a game may give its own text under a key instead). `getText(key, fallback, placeholders)` fills `{placeholders}` literally (split/join, so a value like `$&` goes in as it is), falls back to English, then to the key; `serverErrorText(error)` shows a server's error (it answers in English) in the page's language, a text the lists do not know as it came. Static markup takes `data-i18n` (text), `data-i18n-placeholder`, `data-i18n-title` and `data-i18n-aria-label` (an icon-only button's only name); the `<title>` too, and `<html lang>` follows the language. `i18n.setLanguage(lang)` keeps the choice and fires `languagechanged` on `document`: text a script draws does not react to `data-i18n`, so the page listens and draws again. The language button (`.lang-toggle-btn`) goes at the end of the page's `.container`
- **The server's errors** are English texts written literally — `error: '...'`, `send(ws, 'error', '...')` —, never built from pieces, so `checks.js`'s `serverErrorTexts(files)` finds them. Their Russian copies: the kit's server code's (`shared/`, `worker/`: `KIT_SERVER_FILES`) in `KIT_SERVER_ERRORS` (`i18n.js`; `tests/server-errors.test.js` keeps the two equal), a game's own in its `serverErrors`, which never repeats the kit's (whoami: `translations-real.test.js`). Rewording an error means rewording its key too

### Screen wake lock
`wake-lock.js`: `keepScreenAwake(true)` / `keepScreenAwake(false)` — the game says when (whoami: while a round is on), leaving the page lets go by itself. Silent, as in the owner's other apps (Western Setup): no control, no text; a browser without the Screen Wake Lock API or one that refuses (battery saver) shows nothing. The browser drops the lock whenever the page leaves the screen; coming back (`visibilitychange`) and any tap or key ask again — the tap also covers a browser that refuses a lock asked for without one. The Permissions-Policy must not forbid `screen-wake-lock` (`public/_headers`)

### PWA
`pwa.js` registers the game's own service worker (`/sw.js`) and shows the "Update available" banner (kit's texts) at the top of `.container` when a new worker is installed; it checks for one every 30 seconds and whenever the page comes back on screen. `forceAppUpdate()` in the console updates by hand.
- **The service worker caches icons and nothing else** (`service-worker.js`): a game lives on its server, so offline support is pointless, and caching HTML/JS only ever left players on an old version. The worker exists for installability and free icon caching. A game's `sw.js` names its cache and its icons and hands them over: `importScripts('/kit/js/service-worker.js'); cacheIconsOnly(CACHE_NAME, iconAssets);`. Icons are matched by **exact pathname** (a substring check once matched every URL, `'/'` being in the list); everything else goes to the network untouched. A new cache name drops the old cache: a game bumps it when its icons change. `tests/service-worker.test.js` runs the logic in a made-up worker scope; a game's own test keeps its list to icons
- **Any change to a game's `sw.js` or to the kit's `service-worker.js` is a new worker** of that game, or of every game: browsers compare the imported script too, and every open page shows the banner. Change them only for a real reason

### Security headers
The Content Security Policy, Referrer-Policy, Permissions-Policy, nosniff — the list of the owner's Flying Solo — on every answer of every game: `public/_headers` (copied into each game) puts them on the static files, and a game's Worker on its own answers from `worker/security-headers.json`. The two are deliberate copies (`tests/security-headers.test.js` keeps them equal); the reasons are written in `_headers`, as JSON holds no comments. **One list for every game**: a source one game needs is allowed for all, so each reason in `_headers` says whose it is (`data:` and `blob:` images: the photo avatars of the kit's landing page, and Bootstrap's icons). A game's `site-headers.spec.js` checks what a browser gets — and so catches a copy that did not happen

### Fonts
The games' own files (`public/kit/fonts/`, Fontsource; licenses next to them: Ultra's is Apache 2.0, the others' SIL OFL), never a CDN: the CSP allows fonts only from the game's site. `fonts.css` next to them holds the `@font-face` rules, and a page links it before the style sheets (`playbill.css`, then the game's); a game's style sheet only names the families. Latin and Cyrillic are separate files by `unicode-range` (the browser downloads Cyrillic only for a page that has it), and there are no italic files (nothing is italic; the browser would slant the letters itself). Ultra and Abril Fatface have `font-display: block`: a logo flashing in a fallback serif looks worse than a short pause. Fira Sans Condensed sets the text of every game (`playbill.css`); which face sets a game's sign is the game's look (whoami's CLAUDE.md, Fonts)

### The playbill look
`public/kit/css/playbill.css`: the look every game shares — a parlour-game playbill: cream paper, dark brown ink, the game's accent, on a theatre curtain in the game's color. A page links Bootstrap, the kit's `fonts.css`, `playbill.css`, then the game's `style.css`, which adds what is the game's own (whoami: its sign, the character tags, the envelope and seal, the waiting seal, the join request window) and may use the kit's tokens. What one game draws never goes here
- **Colors are tokens on `:root`** (`--paper`, `--paper-light`, `--ink`, `--ink-soft`, `--accent`, `--red`, `--gold`, `--on-page`…); a game adds its own tokens in a `:root` of its style sheet. Bootstrap is repainted through its own variables — `--bs-btn-*` for buttons, `--bs-secondary-color` (so `text-muted` and `form-text` are `--ink-soft`), `--bs-modal-*`, `--bs-alert-*` — never `!important`. The main button is ink, secondary buttons an ink outline
- **The accent and the curtain are each game's color**: `--accent` paints what the kit marks on paper (the numbers of a list, the room code, the chosen avatar with its `--accent-tint` tile, the coffee plate's words), `--curtain-top` and `--curtain-bottom` the curtain (and the language button's text on hover). They are red unless a game's style sheet sets its own on its `:root` (whoami keeps red; Consequences: bottle green); the game paints its sign's name and its own accents with the same color. **Red (`--red`) is only for what cannot be undone**, the same in every game: `btn-danger`, `btn-outline-danger`, an error's edge (`alert-danger`)
- **The classes it draws**: the curtain on `body`, `.container`, the sheet `.game-card` with its `.sheet-title`, `.tagline` on the curtain, fields and labels, the landing form's `#roomCode` (`.prefilled`), `.avatar-selector` with `.avatar-option` and the `.avatar-shuffle-btn` buttons, `.room-ticket` (the room code in the room's header), `.player-list` with `.player-card`, `.player-avatar`, `.player-name`, the waiting screen (`.waiting-sheet`, `body.waiting-for-admission` hides the room's ticket and sheets), the language button, `.page-foot` with the coffee plate `.bmc-button`, alerts and `.notification`, windows (`.modal`; on a phone `.mobile-friendly-modal`, `.mobile-modal-footer`, `.mobile-modal-btn`), `.desktop-only`
- **Hover effects only for a mouse** — a `:hover` rule goes inside `@media (hover: hover) and (pointer: fine)`: on a touch screen the hover state sticks after a tap (a game's `styles.spec.js` reads both style sheets as the browser took them and checks)
- **Buy Me a Coffee** is a plain link, not the service's widget script (the CSP allows only the game's own code): a small playbill plate, `.bmc-button`, in a game's landing page footer. The cup in it is the service's own logo, unchanged (`public/kit/img/bmc-cup.svg`, `/kit/img/bmc-cup.svg` on a page) — their terms forbid changing their marks
- A change here is a change of every game's look: look at every game's screens after it

### Pictures
A game's app icons and link preview picture are its brand, drawn in its own sources outside `public/` (never served); the kit's commands take them with Playwright's Chromium and write into the game's `public/`. Run in the game's folder:
- `room-kit-icons` (a game's `npm run icons`): `scripts/icon.html` → the manifest's PNGs (`public/icons/icon-48x48.png` … `icon-512x512.png`), the iPhone's `apple-touch-icon.png` and `public/favicon.ico` (16, 32 and 48 px as PNGs inside the ICO). The game bumps its icon cache name after it (PWA)
- `room-kit-og-image` (a game's `npm run og-image`): `scripts/og-image.html`, 1200×630, with the sign of `public/index.html` (`svg.brand-sign`) put into its `.sign-slot`, saved as JPEG where the landing page's `og:image` points. Messengers keep a picture by its address: a new look gets a new file name in the pages' tags, and the command follows it
- The emoji in a picture are drawn by the system's emoji font of the computer that takes it: a picture taken again elsewhere may differ in them

## Rules
1. **Debug output goes through `debugLog()`** (`app.js`), never `console.log` in a page script (ESLint's `no-console` fails on it, `eslint.mjs`). It prints only after `localStorage.setItem('<prefix>-debug', 'on')` and a reload; `console.warn`/`console.error` are for real problems. The Worker and the rooms keep `console.log`: it is what Workers Logs show
2. **The pages share names through plain `<script>` files** — a file lists what it takes from the others in `/* global ... */` and what it gives in `/* exported ... */`: ESLint checks each file on its own. `checks.js`'s `sharedNameProblems` checks the lists across files; a game runs it on its scripts and the kit's together
3. **Every text in both languages**: the kit's texts (`KIT_TEXTS`) and every game's in English and Russian, with the same placeholders (`tests/i18n.test.js`; a game's own test checks its dictionaries)
4. **Only the game's own code runs on its pages** (Content Security Policy, `public/_headers`) — no `style="..."` or `on...="..."` attributes, neither in the markup nor in HTML a script builds: looks go through classes in a style sheet, handlers through `addEventListener`; a script may still set `element.style`. Third-party code goes to `public/kit/vendor/`, never a CDN. A new source in the CSP (another site, `data:`, `blob:`) is a deliberate decision for every game, with a comment in `public/_headers` (and the same value in `worker/security-headers.json`)
5. **The copies of the kit's files in a game are never edited**: change the kit, the next copy brings it

## Gotchas
- **The room socket drops what it cannot send** — `RoomSocket.emit` while not connected sends nothing: a game sends its moves through `sendMove()` (The room page), which waits for the room
- **A deploy keeps the sockets open**: a sleeping room wakes on the new code, its sockets and storage in place; a room that stays awake runs the previous code until it sleeps, new pages included. So for a while after a deploy a room may run the old code next to new pages: a change of the socket protocol must still work with a room on the previous version. A room that Cloudflare does restart drops its sockets: the pages reconnect, and the game's room puts its bookkeeping right as it loads
- **Locally the Worker sees the production host** in `request.url`: `wrangler dev` takes it from the route in wrangler.jsonc. It turns that host back into the local one in a `Location` header, so a redirect stays local; anything else built from `request.url` — an absolute link in an answer, a check of the browser's `Origin` against the host — would name production or fail locally. Answer with paths
- **A new or renamed room class needs a new migration entry** in a game's wrangler.jsonc (`migrations`: `new_sqlite_classes` for a new class — SQLite storage is the kind the free plan has —, `renamed_classes` for a new name); a migration that deletes a class deletes every room's storage with it
- **A game's `public/` is uploaded as it is**, the kit's copy included: a file in it is a file of the site, unless the game's `public/.assetsignore` names it (`.DS_Store` from a Mac); `_headers` and `.assetsignore` themselves are not served
- **A new `bin` of the kit needs its link renewed**: `npm install` answers "up to date" and links nothing. Remove `node_modules/@parlour-games/room-kit` and run `npm install` twice: the first records the bin in the lockfile, the second links it into `node_modules/.bin`; `npm clean-install` in Workers Builds links it from the lockfile

## Decisions (why it is so)
The owner's decisions, with the reason.
- **Bare Durable Objects, one per room** (on Cloudflare Workers, root CLAUDE.md): a room's state, sockets (the WebSocket Hibernation API: a sleeping room costs nothing) and timer in one place. No PartyServer or partysocket: fewer dependencies, all the code in sight, and the room base is the pattern every game follows
- **The kit's browser files reach a game by a copy at build time**, not by symlinks in git (wrangler means to skip symlinks in the static files and uploads them only by accident: a fix on its side would silently drop the kit's files from production), not served by the Worker (every file would be a request of the day's limit, where static files are free), not as committed copies (every file twice: what the monorepo avoids)
- **One list of security headers for every game**: the games follow one policy, the list of the owner's Flying Solo
- **Bootstrap is local, not on a CDN**: the Content Security Policy allows only the game's own site, and the owner's apps share one Bootstrap
- **The fonts are the kit's**: the games share the playbill typography; which face sets a game's sign stays its look
- **The playbill look is the kit's** (`playbill.css`), a game's sign and field are the game's: the games are one collection, and a fix of the shared look reaches every game instead of living in copies
- **The kit's behaviour is tested through the games' browser tests**, never by tests of its own on a page of its own: a game's pages use the kit as players do. The kit's Jest tests check its files — the copies, the two copies of a value, the rules about how code is written, the logic that runs without a page (`debugLog`, the translations)
