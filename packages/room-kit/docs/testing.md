# Тесты игр на ядре

Общие правила тестов каждой игры с комнатами на ядре. Своё у игры — её команды с именами файлов, серверы тестов, помощники и особые тесты — в её `docs/testing.md` (whoami: `games/whoami/docs/testing.md`). Поведение ядра проверяют браузерные тесты игр: страницы игр пользуются ядром так же, как игроки (CLAUDE.md ядра, Decisions); собственные тесты ядра — Jest в `packages/room-kit/tests/`.

## Команды

Все проверки игры — `npm test` в её папке: ESLint, затем Jest, затем браузерные тесты Playwright. Перед слиянием ветки — `npm test` из корня репозитория: проверки ядра и каждой игры. CI нет: этот прогон — единственная проверка до `develop` и прода.

Из папки игры (`games/<игра>/`). Скрипты npm то же самое делают из корня с `-w games/<игра>`; `npx jest` и `npx playwright` — только из папки игры: их настройки лежат в ней.

```bash
npm test                                   # всё
npm run lint                               # только ESLint
npx jest                                   # только Jest
npm run test:e2e                           # только браузерные тесты
npm run test:e2e:headed                    # с видимым браузером
npm run test:e2e:ui                        # интерактивный режим Playwright
npm run test:e2e:prod                      # браузерные тесты против прода (после выкладки)
```

Проверки самого ядра — ESLint и Jest: `npm test -w packages/room-kit` из корня или `npm test` в `packages/room-kit/`.

На новом компьютере один раз: `npx playwright install chromium`.

## Два вида тестов

| Что | Где | Чем |
|---|---|---|
| Правила игры: её `game-logic.js`, хранение и таймеры комнаты, проверка ввода, сверка копий, которые игра держит намеренно, правила того, как написан код | `tests/*.test.js` | Jest, в Node |
| То, что видит и делает игрок: страницы, кнопки, окна, несколько игроков в одной комнате; что видит бот мессенджера по ссылке; стили, как их прочитал браузер; ответы HTTP API | `tests/e2e/*.spec.js` | Playwright, в Chromium |

Куда писать тест:
- **правило игры** — Jest, функция из `game-logic.js` вызывается напрямую;
- **маршрут HTTP** — Playwright, через `request` без страницы;
- **всё, что игрок видит или делает** — браузерный тест;
- **новый экран или окно** — ещё и проверка axe.

Поведение проверяется через страницы и ответы сервера, а не поиском по коду. Тест, который ищет в файле `navigator.share`, остаётся зелёным, когда кнопка сломана. Код игры тест к себе тоже не копирует: копия подтверждает сама себя.

Правила о том, как написан код, тест проверяет по тексту файлов: правило и есть про текст. Проверки дают ядро (`checks.js`), игра зовёт их со своими папками: `inlineCodeProblems` — ни `style="..."`, ни `on...="..."` в страницах и в HTML, который собирают скрипты; `sharedNameProblems` — общие имена скриптов страниц, игры и ядра вместе; `serverErrorTexts` — тексты ошибок сервера, у которых должен быть перевод. Копии, которые держит ядро (заголовки безопасности, формат ID игрока, лимиты имени и фото-аватара, переводы ошибок его серверного кода), сверяют тесты ядра; копии игры — её тесты.

## Проекты Playwright

| Проект | Устройство |
|---|---|
| `mobile` | Pixel 7 — первым: в игры играют с телефонов |
| `desktop` | Chrome на компьютере |

Общие настройки — `packages/room-kit/playwright.js`: проекты (только Chromium, user agent помечен как проверка — «Против прода»), `use`, таймауты для прода, команда `wrangler dev`; `playwright.config.js` игры задаёт свои порты и серверы. Playwright сам запускает `wrangler dev` — движок Cloudflare с Worker, комнатами и файлами, как на проде, — и каждый раз заново, так что тесты всегда видят текущий код (а wrangler перед стартом копирует в `public/` игры файлы ядра). Второй сервер с короткими таймерами комнаты (`vars`: `ROOM_EMPTY_MS`, `GHOST_MS`) нужен только тестам таймеров; остальные его не трогают.

Запущенный `npm start` не мешает: у тестов свои порты. Хранилище комнат серверы тестов пишут во временные папки (`--persist-to`), а не в `.wrangler/`.

В тестах язык браузера — английский, анимации Bootstrap выключены (`reducedMotion`), service worker включён, как у игроков. Проверка axe отключает на странице CSS-переходы: иначе цвет кнопки, который меняется под пальцем, замеряется на полпути. Правило вписывается в собственную таблицу стилей страницы (`insertRule`): добавленный тег `<style>` CSP заблокировала бы.

Все тесты идут под той же Content Security Policy, что и прод: её ставят `public/_headers` (копия из ядра) на файлы и Worker на свои ответы. Страница ничего не грузит с других сайтов (это проверяет тест заголовков игры), так что интернет нужен только прогону против прода.

## Игроки и страховка

Игроки и страховка — `packages/room-kit/e2e.js`: `tests/e2e/helpers.js` игры берёт оттуда `test` и `expect`, передаёт дальше помощники ядра (ниже) и добавляет свои.

`newPlayer(имя, { locale })` открывает отдельный профиль браузера на устройстве текущего проекта: у каждого игрока свой localStorage, а значит свой ID. После теста профили закрываются.

Страховка: тест падает, если на странице любого игрока случилась ошибка JavaScript, `console.error`, нарушение Content Security Policy (фикстура превращает его в `console.error` с названием правила) или окно браузера (`alert`, `confirm`, `prompt`: сообщения игры — её собственные окна). Одно нарушение страховка пропускает: его создаёт сам Playwright, когда записывает трассу и копирует картинку страницы с адреса `blob:`. Тест, который ждёт ошибку в консоли, говорит об этом явно: `player.allowConsoleError(шаблон)`.

## Помощники ядра (`packages/room-kit/e2e-helpers.js`)

Помощники, которые действуют через страницы ядра — по `id` его договора о разметке и по карточкам игроков `.player-card` (своя подписана «Имя (You)» на языке страницы). Игра передаёт их дальше из своего `tests/e2e/helpers.js`; свои помощники игры — в её `docs/testing.md`.

| Помощник | Что делает |
|---|---|
| `pageTexts(translations.js)` | тексты страниц игры поверх текстов ядра, как на странице: `text(ключ, язык, подстановки)` — строка с заполненными подстановками, `serverErrorText(текст, язык)` — ошибка сервера (он отвечает по-английски) так, как её показывает страница на этом языке; тексты игры в тестах не пишутся руками |
| `seedStorage(игрок, значения)` | кладёт значения в localStorage игрока (ключи игры хранят JSON) |
| `waitForLanding(page)` | ждёт, пока главная страница подготовится (12 аватаров) |
| `createRoom(игрок)` | создаёт комнату с главной, возвращает код |
| `joinRoom(игрок, код)` | ссылка на комнату → `/?join=КОД` → имя → «Join» |
| `askToJoin(игрок, код)` | то же в начатый раунд: страница комнаты ждёт, пока игрока впустят (`#waitingSheet`) |
| `playerCard(page, имя)` | карточка игрока; своя подписана «Имя (You)» |
| `waitForPlayers(page, число, { timeout })` | ждёт столько карточек |
| `roomWith(newPlayer, имена)` | комната этих игроков, все на её странице и видят всех |
| `leaveGame(игрок)` | «Leave» → окно → подтверждение → главная |
| `answerMessage(page, текст)` | окно сообщения ядра показывает этот текст, игрок нажимает его кнопку |
| `iconsOf(page)` | сколько на странице значков и у каких нет рисунка (`{ count, broken }`) |
| `stubShare(page, 'record' / 'abort' / 'unsupported')` | подменяет системное окно «Поделиться» (настоящее остановило бы браузер); вызывать до загрузки страницы |
| `expectCopyButtonsOnOneLine(page, кнопки, ширины)` | каждая кнопка держит надпись в одну строку, и «Скопировано!» после нажатия тоже — на ширине окна, потом на каждой из `ширины`; страница пишет в буфер обмена и без Web Share (`stubShare(page, 'unsupported')`), так что «Поделиться» тоже копирует |
| `hideSocialWidgets(игрок)`, `socialWidgetsHidden(page)` | браузер игрока прячет то, что прячет список «социальных виджетов» блокировщика рекламы (Fanboy's Social): его правила дописываются после стилей ядра; вызывать до загрузки страницы. `socialWidgetsHidden` говорит, что правила на странице |
| `countSentEvents(page, событие)` | считает события, которые страница отправила в сокет комнаты; вызывать до входа в комнату |
| `holdRoomJoin(page)`, `releaseRoomJoin(page)` | медленная связь: страница рисует комнату после HTTP-входа, а `join-room` её сокета уходит только после `releaseRoomJoin`; вызывать до загрузки страницы |
| `pngFile()` | настоящая PNG-картинка, собранная в коде |
| `PAGE_STATUS_404` | сообщение консоли о странице со статусом 404: тест, который открывает такую страницу, ждёт его (`player.allowConsoleError`) |

## Сокет комнаты в тестах

Страница говорит с комнатой через `RoomSocket` ядра (`public/kit/js/room-socket.js`); внутри `page.evaluate()` он доступен как `socket`.
- **Обрыв связи** — `socket.ws.close()`: страница сама подключается снова (через секунду-другую) и входит в комнату заново. С `context.setOffline(true)` до закрытия новое подключение не удастся, пока сеть не вернут.
- **Второй сокет из консоли** — `new RoomSocket(`/ws/${код}`)`: так игрок-злоумышленник пробует действовать за других.
- **Медленная связь** — подмена `WebSocket.prototype.send` до загрузки страницы (`page.addInitScript`), которая придерживает кадр с `"event":"join-room"`: страница уже нарисовала комнату после HTTP-входа, а её сокет ещё не в комнате.
- **Таймеры комнаты** (часы без страниц, час для «призраков») проверяются на втором сервере, где это секунды. Против прода такие тесты пропускаются.

## Правила набора

1. **Ожидания берутся из данных игры** (`translations.js` игры и тексты ядра, ответы сервера), а не переписываются руками: копия в тесте расходится с игрой при первой правке и начинает подтверждать сама себя.
2. **Новый тест хотя бы раз ломают.** Тест на исправление падает на старом коде (из папки игры: `git stash push public worker game-logic.js`, прогон, `git stash pop`; правка ядра — тем же путём в `packages/room-kit/`); тест на уже работающее поведение падает, если на минуту испортить код. Тест, который не падает на сломанной игре, ничего не проверяет.
3. **Никаких пауз «подождать 2 секунды»** (`waitForTimeout`): тест ждёт условие, `expect(...)` сам повторяет проверку.
4. **«Ничего не произошло» проверяется в известный момент.** `expect(...).not...` ждёт, пока условие станет верным, а надпись «Copied!» и уведомления исчезают сами — такой тест проходит и на сломанной игре. Состояние читается один раз после точки синхронизации: сразу после вызова или после события, которое пришло позже.
5. **Каждый тест создаёт свою комнату**: тесты идут параллельно и не мешают друг другу, в том числе на проде.
6. **Действовать как человек**: сначала страница готова, потом клик; элемент, который пропускает касание сквозь себя, нажимается в точке, где он нарисован (`page.mouse.click`).
7. **Пропуск — только с причиной**: `test.skip(условие, 'почему')`.
8. **Селекторы**: роли и подписи (`getByRole`), `id`, `data-*`. Если зацепиться не за что — добавить подпись (`aria-label` с переводом) или `data-*`: подпись поможет и экранному диктору.

## Отладка

- Трассы по умолчанию не пишутся: запись делает снимок страницы после каждого действия каждого теста, и в полном параллельном прогоне эта нагрузка изредка подвешивала страницу — тест падал при исправной игре. Разобрать падение: прогнать с трассой (`npx playwright test <файл> --trace on`, плавающий тест — вместе с `--repeat-each`) и открыть её: `npx playwright show-trace test-results/<тест>/trace.zip`. Отчёт прогона — `npx playwright show-report`.
- `npm run test:e2e:headed` или `npm run test:e2e:ui`, чтобы видеть страницу.
- Журнал игры в консоли: `await player.page.evaluate(() => localStorage.setItem('<префикс>-debug', 'on'))` и перезагрузка (префикс — `APP_STORAGE_PREFIX` игры).
- Плавающий тест — прогнать много раз: `npx playwright test <файл> --repeat-each=10`.

## Против прода

`npm run test:e2e:prod` гоняет те же браузерные тесты против адреса игры (`BASE_URL`) — после каждой её выкладки (`docs/release.md` в корне репозитория). Тесты создают на проде свои комнаты. Комнату удаляет последний вышедший; остальное убирает сама комната: игроков «не в сети» дольше часа, пока кто-то играет, и комнату через 2 часа после того, как закрылась последняя страница. Таймауты больше, а браузеров одновременно два (`--workers=2` в команде), а не половина ядер, как дома: до прода идёт настоящая сеть, и чем больше игроков разом, тем вероятнее, что какой-то ответ не успеет до таймаута. Прогон расходует дневной лимит запросов Cloudflare, общий для всех приложений владельца (корневой CLAUDE.md, Decisions).

Запросы тестов помечены, как во всех проектах владельца: user agent заканчивается на ` EscapistCheck`, и в аналитике Cloudflare их убирает фильтр «Source user agent does not contain EscapistCheck». Остальное не меняется — телефон остаётся телефоном. Метку ставят проекты (`markedDevice` в `packages/room-kit/playwright.js`), дважды: `userAgent` — страницам, их файлам, сокетам и `request`; флаг запуска браузера `--user-agent` — тому, что браузер скачивает сам: без него скрипт service worker'а (`/sw.js` и каждая проверка обновления) уходит как `HeadlessChrome`. curl к проду — с `-A "curl EscapistCheck"`.

Метку держит `tests/e2e/check-tag.spec.js` каждой игры — тест ядра `packages/room-kit/e2e-check-tag.js` на настройках игры. Он поднимает свой сервер (на прод ничего не шлёт и в прогоне против прода) и проверяет, что метка доходит от страницы, от загруженного ею файла, от её service worker'а и сокета и от прямого запроса, а остальное — user agent устройства. Метка вписана в тест строкой, а не взята из настроек: её случайная правка роняет тест, а не молча ломает фильтр.
